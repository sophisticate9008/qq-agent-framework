# 架构与缺口

日期：2026-10-24。目标是能组合不同功能的桥接基础件，不是某个单一的生图机器人。

## 为什么独立建设

旧桥接的本机工作树已承载大量会话行为和维护改动。继续把调度、权限、产物、功能加载和
个性化需求混在生产入口，会提高回归和并行编辑成本。用户因此要求参考旧项目、独立起框架。
既有成功资源、原型、会话、部署和其他会话的未提交修改全部保留，不以“重写”作为删除它们的理由。

本轮选择性核查了旧交接、相关加载/转发模块、唤醒与外发路径及本机离线记录。
历史“插件 active”“素材生成成功”不能升级成“指定旧/新受限会话可调用并送达”的结论。
DSH 的注入与会话快照生命周期仍需独立定位；不能从同一错误文案推断缓存根因，也没有证据说明需重写 DSH。

## 层次

```text
可信宿主 / 显式工作流
  ├─ persona、configuration、preferences 各自入口
  ├─ policy：作用域授权、预算、暂停、撤销
  ├─ eventValidators：新增事件契约
  └─ effectAdapters：新增能力实现（以后接 QQ / DSH / 资源 / 生成服务）
           ↓
内核：生命周期、事件队列、功能 SDK、私有状态、受控副作用、脱敏审计
           ↓
功能包：对话 / 提醒 / 将来的自身形象表达 / 其他用户工作
           ↓
本地 UI：展示快照、手动演示；不执行任意源码、不创建额外授权
```

`src/core/types.ts` 定义功能、事件、适配器和回执的 TS 契约。
`src/core/engine.ts` 不导入具体功能、不加载生产配置、不在模块导入时绑定端口。
`src/app.ts` 是显式装配根，不是隐式全局服务定位器。

## 当前挂载点

| 挂载点 | 当前实现 | 不能据此宣称 |
| --- | --- | --- |
| 功能安装/卸载 | 版本化 manifest、事务发布、AbortSignal、执行排空、逆序清理 | 不可信代码沙箱、跨版本状态迁移、运行中代码热替换 |
| 事件 | 两个内置事件；宿主可新增同步数据校验器 | 持久定时器、可靠消费、旧会话能力刷新 |
| 能力 | 两个内置路径；宿主可新增具名 effect adapter，通过 invoke 调用 | 任意聊天能注册新能力、任意代码能被安全执行 |
| 上下文 | 分层、独立的数据快照与来源；临时偏好到期恢复默认 | 完整业务 schema、持久数据库、用户身份认证 |
| 状态 | feature + conversation 的私有命名空间 | 事务任务存储、跨进程隔离或恢复 |
| 权限 | 精确功能/会话/能力、有限尝试预算、撤销与暂停 | 已开始外部动作可回滚、安装声明自动等于授权 |
| 观测 | 脱敏阶段/结果码、版本、事件和会话关联 | 持久审计、真实网关回执、全部链路的分布式追踪 |
| UI | 本地认证快照、两个手动演示 | 工作发布台、远程多用户权限管理、生产运维控制台 |

事件同会话顺序、跨会话并发；发送默认全局顺序，宿主可用 maxConcurrentSends 显式选择有界跨会话并行，
此时同会话仍有序，真实适配器是否支持并行必须另外验收。默认最多 256 个未结束事件、512 个未结束
副作用；保留 500 条审计和有限完成历史。这是进程内限流，不是完整资源配额。
去重只在内存保留窗口内有效；超出窗口或重启后不能保证同一事件不重做。
模型生成和通用能力不自动重试、不提供幂等存储；适配器应按各自外部协议设计恢复。

迭代002补充：订阅按事件索引；偏好和授权按精确作用域索引，避免每个事件扫描所有用户数据。
yieldEvery 默认64、yieldAfterMs 默认8，任一阈值触发协作式让出；不使用状态的执行不分配空命名空间。
metrics() 只返回计数和调度状态，describe() 仍是完整管理快照，不应作为高频健康轮询。
性能实测与最坏命中/内存等限制见 PERFORMANCE；不得把较高吞吐当作生产完成证明。

## 人设不等于行为

人设记录“是谁”；功能记录“可以实现什么”；行为配置记录“按什么参数运行”；偏好记录
“倾向怎样表达”；运行状态记录“现在做到了哪一步”；权限记录“获准对哪里做哪些操作”。
固定定义可以由显式工程变更发布新版本，不能被普通聊天推断改写。动态数据也不能改变权限。
配置和偏好只在功能内按明确的字段级规则取值，不能合并成一个万能对象再影响所有底层服务。

## 自身形象表达的正确落点

“以后早上、饭点或合适时用自己的形象表达一下”是主人交给工作 agent 的能力建设任务。
将它记录为偏好，不会产生调度、固定资源访问、生图、审图、兜底和交付能力。
将来应由独立功能包组合这些基础件：

1. 认证工作入口与受约束开发任务：需求、验收、作用域、预算和可部署产物。
2. 持久触发服务：早晨、饭点、中午、下午、夜间、季节是候选事件，不是无条件发言命令。
3. 资源服务：人设版本关联的固定参考和已批准素材，不接受任意路径/模型自行改身份锚点。
4. 产物任务：固定身份生图，轻量检查明显差错；最多一次打回重做。
5. 有限终态：第二次仍不合格则丢弃候选，从兼容身份版本的已合格旧图中随机选择；无合格旧图则跳过图片。
6. 语境门控：对话是否适合、是否忙、冷却/安静时段/频率/会话授权均需检查。
7. 统一出站：择机发送，记录确定回执；结果未知不能盲目再发或统计为成功。

以上流程**尚未实现**。已有通用事件/能力挂载点可以承载其开发，但并不自动具备持久任务、
图片处理、资产审核或 QQ 外发能力。首轮没有调用 image generation，也没有修改旧主动行为开关。

## 下一步优先级

先建立持久任务与出站恢复、资源/产物契约和版本化能力接入证据，再接 QQ/DSH。
工作 agent 的开发/测试/装配/审批链应显式存在，不让聊天模型直接改宿主授权或执行任意部署。
通过两个以上真正不同的功能检验基础件复用，不为单个“早安图”把业务规则固化到核心。
