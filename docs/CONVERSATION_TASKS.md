# 会话任务与续聊

## 在会话中安排任务

在 QQ 里明确委托，例如“十分钟后提醒我喝水”“每天九点提醒我检查日程，到月底结束”“这个后台任务完成后，把结论告诉我”。模型用 `qbf_task_create` 保存目的、等待条件、截止时间、上下文和步数预算，返回任务编号后才表示安排成功。框架到条件满足时唤起原会话，模型可以查询、执行现有工具、发言、创建子任务或继续等待。

这是框架内置能力，启动聊天后运行。任务触发不受 90 秒续聊窗口限制。运行中会重新检查白名单与工具权限，敏感工具仍只认当前配置主人。任务保存原委托人，事件中的文字不改变身份或权限。任务工具与其他工具一样需要可用的 DSH 工具通道。

- `qbf_task_list`：分页查看当前会话的状态、编号和版本。
- `qbf_task_update`：按最新版本修改等待中的任务；切换模型会话后，明确更新可把已结清任务绑定到当前上下文。更新不能增加原截止期限或预算。
- `qbf_task_control`：暂停、恢复、取消、核对，以及删除已结束且已核清的任务记录。活跃任务先取消，未知执行先核对；被未结束任务引用时不能删除。删除保留去重凭据及尚在保留期内的执行证据，防止旧调用把任务重新创建。取消会阻止后续接续，并取消未结束的子任务；已发生的外部动作不会撤销。
- `qbf_task_continue`：任务触发的执行中保存结果、进度和下一次等待；本轮确认完成后才应用。普通会话不能冒充任务执行调用它。

“任务与日程”通过“会话任务”“插件日程”“插件执行记录”页签切换查看，默认显示会话任务；切换保留本页筛选与分页，隐藏页签暂停自动读取。

管理操作由创建者或配置主人在所属 QQ 会话提出。控制台“任务与日程 → 会话任务”展示分页状态与最近执行记录，只读，不提供模型提问或批准按钮。

## 条件与执行

条件支持绝对时间 `at`、相对延迟 `delay`、带 IANA 时区的每日时间 `daily`、相关事件 `event`、依赖任务终态 `task`，以及 `any` / `all` 组合。条件最多四层、32 个叶子，每层最多八项。延迟至少一秒。每日计划遇到夏令时重复时刻取第一次，不存在的时刻跳过；停止期间错过的每日触发恢复后合并执行一次，不补发每个历史周期。

事件以账号、会话、主题、关联键隔离并持久去重。内置 `conversation.message` 以实际发言者 QQ 号为 key，`work.completed` 以后台 workId 为 key。任务创建后、下一次等待登记前已到达的事件仍可匹配；同一事件不会被同一任务反复消费。后台事件提供结果标识，完整结果按现有工作查询接口读取。依赖任务条件在完成、失败、取消或过期时满足，模型应先检查终态，不能把“结束”当成“成功”。

一次触发产生稳定的运行编号，接入原有执行日志、会话队列、工具 policy 和发送回执。相同模型会话串行；新的用户消息优先于尚未接纳的任务。默认并发四个，单轮最多五分钟并受任务截止时间限制。模型未登记继续等待时本次任务结束；每日任务继续下一周期，停止每日任务使用取消。

默认绑定原 sessionId 和 generation。会话被重置或换绑后不会偷偷换到新上下文；明确更新任务才重绑。框架不保证外部系统“恰好一次”，由稳定执行标识、幂等回执、租约和代际校验阻止重复提交与迟到结果覆盖。

## 恢复、容量与清理

已证明未接纳的执行可以延迟重试；中断、超时或结果无法确认时进入“结果待核对”，不自动重放。先通过执行记录核对原执行，再在 QQ 请求核对任务；`reconcile` 只读取原执行证据。后端不能提供证据时保留未知状态，可取消后重新明确委托。取消也不代表远端已经停止，未结的执行证据继续保留。

一个运行实例最多保留 512 个任务，每个会话最多 64 个未结束任务；根任务和所有子任务共享创建与执行预算（最多 1000），子任务截止时间不得超过父任务，最长安排到一年内。完成记录通常保留七天，被未结依赖引用的任务延后清理；未知执行不按已完成清理。创建回执保留到原截止时间后七天，防止清理后重放旧创建请求。事件最多 1000 条，至少保留七天，并覆盖当时未结任务的截止期限；容量满时明确拒绝新增，保留现有证据。存储另有全局容量上限。

页面每批 20 个任务；执行详情最多显示最近 100 条。内存和页面均不依赖无限追加列表。

## 扩展执行器

SDK 导出 `createConversationTaskRuntime`、任务契约与解析器。存储须支持原子 CAS；默认宿主使用 SQLite。执行器注册 `version: 1`，实现 `execute(task, run, signal)`、只读 `inspect(task, run, signal)` 和可选 `cancel`。外部副作用继续由适配器承担，执行器必须遵守信号、稳定 run.id 和自己的回执协议。

`NativeChatRuntimeOptions.taskExecutors` 可登记额外执行器，`taskService()` 向可信宿主代码提供创建任务、发出事件、查询和管理入口。模型直接创建默认只开放 `conversation` 执行器；扩展宿主负责自己的权限与输入校验。检查点、后续等待和执行器返回的子任务在一次事务中应用；模型直接调用创建子任务工具则以该工具的独立持久回执为准。

当前内置后端是在本机原 QQ 会话接续执行。远程执行器可接入上述端口，但本版不包含远程工作节点、跨机调度控制平面或任意 cron 表达式。

## 续聊设置

“概览 → 当前聊天 → 续聊策略”同时设置基础续聊时长与每轮决定发言后的追加时长，设置随当前人设保存并即时用于后续输入。

同处可设置“群聊概率唤醒”：默认每条消息 1%，0% 关闭，最大 100%，支持 0.5% 等小数。仅白名单内尚未唤醒、没有排队或执行中的群聊参与抽取，命中即进入普通唤醒流程并激活基础续聊窗口；保留真实发言者与消息指向，不把普通闲聊说成有人 @ 或提问。已经激活或处理中的群聊不会重复抽取。概率唤醒和直接呼叫都不要求模型一定发言。

基础时长默认 **90 秒**。真实 @（包括只有 @ 和空白）、昵称呼叫、开启引用唤醒后的引用机器人消息，以及协议确认的戳一戳，会激活或刷新窗口。文字模仿“戳一戳”不算协议唤醒。纯 @ 或戳戳到达时，有未读内容就处理有界未读，没有未读时把招呼交给模型。窗口内所有发言者的消息可进入模型参与判断，包括 @ 或引用其他人的消息；模型仍可以保持安静。

追加时长默认 **0.5 秒**。只有本轮输出通过新消息覆盖检查、确定要发言后才按执行编号增加一次；拆成多个短气泡仍是一次，仅处理、静默或被覆盖而未发言不增加。不以成功发送条数计数，也不会将基础 90 秒重新计时。剩余时长持续随时间减少，最多 300 秒；处理期间原窗口已经耗尽时，只获得本次追加的时长。再次真实呼叫重新开始基础窗口。

基础设置 0 关闭续聊，追加设置 0 关闭动态追加。私聊本身持续可参与，不依赖群聊续聊窗口；停止运行会清除临时激活记录，重启不从历史回复恢复续聊。

## 模拟验证与时间核对

“任务与日程 → 会话任务”合并 QQ 与最近四轮模拟的任务，模拟条目直接标记“模拟”，共用表格与详情。QQ 每批 20 条，每轮模拟合并最多 20 个任务与 20 条最近执行；使用虚拟列表限制挂载行数。临时任务删除后，保留期内的执行记录仍可查看。新执行会保存任务名称与所属会话，旧执行缺少名称时显示任务编号。模拟运行停止后不会继续触发，模拟回复只在本地捕获。

`delay` 从任务保存（或登记下一次等待）开始计算，创建工具同时返回绝对触发时间。模型确认回复应说明具体时刻；确认回复生成期间倒计时已经开始。条件满足后还需等待原会话空闲及模型处理，因此实际提醒可能晚于触发时刻。
