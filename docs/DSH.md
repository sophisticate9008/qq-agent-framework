# DSH 接入与运行边界

本框架通过官方 DSH SDK 的 HTTP/WS 协议连接独立 DSH 实例。DSH 的独立安装与基础运行方式见 [官方项目](https://github.com/deepseek-ai/deepseek-harness)；接入时以本文的兼容版本为准。DSH 执行模型请求，本框架管理 QQ 来源、会话绑定、参与规则、权限、副作用和恢复证据。连接成功、请求受理、模型完成和 QQ 投递确认分别记录。

日常收发不重复读取和解析 DSH 配置。全量部署核验放在启动、应用与明确的部署诊断；运行中的状态页复用已核验的部署快照。每次副作用仍读取当前框架配置检查白名单和兼容性，敏感操作核对真实主人。手动更改 DSH 配置后，应应用或重启聊天以更新部署快照。

框架工具挂载时，适配器将参数描述转换为 DSH 支持的 JSON Schema 子集：可空类型使用 `oneOf`，`enum`／`const` 补全类型，长度、数值范围、格式等限制写入字段说明并由宿主工具校验器执行。工具挂载未完成时不提交模型请求；适配器错误码保留到运行状态与活动日志，会话诊断显示挂载阻断。启动会核对并恢复已有会话中未完成的工具挂载，不重放原消息；不能用连接成功代替工具就绪。

## MCP 服务的注册与停用

DSH 启动时会加载已启用的 MCP 服务；stdio 服务由 DSH 启动独立进程。服务可以先注册工具，再在调用时连接 QQ 协议端，因此工具已登记不代表协议端在线。DSH 支持通过工具列表变更通知动态更新注册；服务若没有发送通知，下游停止不会自动撤销工具。DSH 自身未运行时不会接收或执行这些调用。

停用服务应在 Cordis Loader 对应条目上设置 `disabled: true`，与 `id`、`name`、`config` 同级，让加载器卸载服务并撤销其工具。只停止下游进程或关闭重连不能代替停用。独立聊天预设若还声明了同名工具，也需要分别停用或调整；工具清单应核对所有注册来源。停用注册不需要删除协议端安装、会话或切换时需要的配置。

## 版本与安装

当前桥接插件是 `@qq-bridge-framework/dsh-bridge-plugin` **1.5.3**，适配官方 DSH SDK **0.2.1-rc.2** 和 Cordis **4.0.5**。框架要求 Node.js **24.12.0 及以上**。插件清单中的 SDK peer dependencies 使用精确版本；升级 SDK 后需重新验证协议和运行行为。


### 安全依赖覆盖

该版 DSH SDK 的依赖锁定包含 `zod@4.4.3`，受 [Zod 集合校验内存耗尽告警](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) 影响；修复版从 `4.6.6` 起提供。插件开发与 CI 锁文件使用 `zod@4.6.7` 覆盖。

**依赖包的 `overrides` 不会自动作用于独立 DSH 宿主。** 在你管理的 DSH Node 项目根 `package.json` 中合并以下字段，保留已有依赖和其他覆盖设置，再按该宿主的安装流程更新锁文件并重新加载：

```json
{
  "overrides": {
    "zod": "4.6.7"
  }
}
```

此示例是 npm 的根项目配置；其他包管理器使用自身的覆盖机制。如果宿主直接依赖 Zod，需同时核对直接版本与覆盖约束。更新后检查 `npm ls zod` 与 `npm audit`，并核对 DSH 的会话、工具和桥接加载。安装桥接 tarball 不会替宿主修改这些设置，框架也不会自动改写已运行实例的依赖。SDK 与 Cordis 的精确兼容版本保持不变。


使用 pi-ai **1.4.0** 和 `@deepseek-ai/dsh-llm-pi-ai` **0.2.1-rc.2** 时，可在仓库根目录执行 `node scripts/patch-dsh-responses-usage.ts /absolute/path/to/dsh-node-project`，安装 Responses 与 Chat Completions 用量兼容解析器。脚本核对两个包的版本和解析块，为修改的三个文件保留 `.qbf-usage-original` 备份，编译 TypeScript helper 后逐文件原子替换；支持更新旧 Responses 补丁及重复执行。安装后按维护流程重启 DSH。

解析器保留上游是否明确报告缓存计数，明确的零也通过 DSH 标准可选字段传递；未报告的缓存读取保持未知。Responses 兼容标准及网关缓存、输入输出别名，Chat Completions 保留原有数值映射。请求协议由当前模型配置选择，安装补丁本身不切换协议。缓存分项未知时仍保留可确认的总输入和输出，历史账本与已有金额不重写。网关实际未报告的缓存量无法恢复，升级或重装依赖后需重新核对；版本或源码不符会拒绝安装。

下一次实际模型调用后，pi-ai 的 `dist/api/qbf-provider-usage-observed.json` 保留最近一次上游用量诊断：只包含白名单数值计数、缓存报告标记及时间，不记录请求、正文或凭据。文件以 `0600` 权限原子覆盖，不累积历史；诊断写入失败不影响聊天。它用于区分网关缺少缓存字段与下游映射丢失。

插件当前通过本仓库构建的 tarball 安装，未提供公开 npm 发布安装承诺。在框架仓库根目录执行以下命令可生成安装包：

```sh
npm --prefix packages/dsh-bridge-plugin ci --ignore-scripts --no-audit --no-fund
npm --prefix packages/dsh-bridge-plugin run build
artifact_dir="$(mktemp -d)"
(cd packages/dsh-bridge-plugin && npm pack --ignore-scripts --pack-destination "$artifact_dir")
printf '安装包目录：%s\n' "$artifact_dir"
```

记下输出的 `.tgz` 绝对路径。在你管理的独立 DSH Node 项目目录中明确安装它，例如：

```sh
npm install --ignore-scripts /absolute/path/qq-bridge-framework-dsh-bridge-plugin-1.5.3.tgz
```

安装前核对该实例的 SDK 版本与锁文件。安装包只包含公开清单及编译后的插件文件，不包含框架配置、凭据或会话数据。隔离打包验收会在临时项目中安装真实 tarball，核对既有依赖的版本和完整性，并运行官方 SDK 的加载及 owner 认证测试。

## 将插件加载到 DSH

安装 npm 包后，还需让独立 DSH 实例的 Cordis 启动过程加载它。已经实际验证的入口是官方 `@deepseek-ai/cordis-plugin-loader` **1.0.6**。若实例尚未提供 Loader，先在该独立项目中明确安装：

```sh
npm install --ignore-scripts @deepseek-ai/cordis-plugin-loader@1.0.6
```

然后在其启动装配中使用：

```ts
import type { Context } from '@deepseek-ai/cordis';
import Loader from '@deepseek-ai/cordis-plugin-loader';

// 在独立 DSH 的启动代码中调用；ctx 是该实例已有的 Cordis Context。
// 此示例适用于尚未安装 Loader 的 ctx。
export async function loadFrameworkBridge(ctx: Context): Promise<void> {
  const loader = ctx.plugin(Loader);
  await loader.inertia;
  await ctx.loader.create({
    name: import.meta.resolve('@qq-bridge-framework/dsh-bridge-plugin'),
  });
  await ctx.loader.await();
}
```

调用前，该 DSH Context 必须已经提供 `agents`、`agentPresets`、`tools` 和 `typertGateway` 服务。已有 Loader 的实例复用原 Loader，只执行 `create` 和 `await`；同一实例只加载一份桥接插件。实际集成测试还装配官方 session、projection、system prompt、LLM、registry、remote access、gateway、preset 和 agent loop 服务，覆盖了插件入口及真实 session controller。

上例是经过测试的程序加载 API。现有 DSH 实例如何持久保存这段启动装配，应由该实例自己的启动管理方式决定。本框架没有提供已验证的通用永久 Cordis YAML 插入方案，不会在控制台连接或应用方案时自动安装 npm 包或首次加载插件。已受管实例在应用现有会话提示词或助手配置时，可能通过本机维护服务重启 DSH，见下文。

插件通过 owner 认证后的 `bridgePlugin/describe` 声明 `qq-bridge-framework.dsh-bridge/1`、插件和 SDK 版本、当前 `issuerEpoch` 及证据保留能力。普通模型工具调用者不能借用这个管理身份。

图片工具结果通过 Agent 上下文的 `get('attachments')` 获取可选附件服务，再保存为 SDK 图片附件。Agent 上下文未注入该服务，不能直接访问 `agent.ctx.attachments`。附件处理失败会结束当前工具调用并返回 SDK 错误码或 `TOOL_MEDIA_PROCESSING_FAILED`，不会将单次图片失败升级为整个工具通道故障；来源变化返回 `TOOL_MEDIA_SOURCE_CHANGED`，取消返回 `TOOL_CALL_CANCELLED`。

对应实现与真实加载测试见 [插件入口](../packages/dsh-bridge-plugin/src/index.ts)、[官方 SDK 加载测试](../packages/dsh-bridge-plugin/test/sdk-entry.test.ts) 和 [隔离打包验收](../packages/dsh-bridge-plugin/scripts/verify-packed.ts)。

## 本机连接与鉴权

在控制台连接页选择“自动连接本机 DSH”。默认路径会寻找同一系统用户运行的 DSH web 服务，识别其 `DSH_HOME` 和回环地址，读取本机鉴权配置并验证服务。用户无需重复填写地址、令牌或凭据文件路径。

当前自动鉴权实现面向 Linux：从 `/proc` 有界读取同用户 DSH 进程信息，并尝试发现的地址及本机候选端口。候选验证有数量和总时间上限，不扫描任意远程地址。本机凭据文件必须是当前用户拥有、权限为 `0600` 或 `0400` 的普通单链接文件；实际读取拒绝路径替换、符号链接和不安全文件。认证材料只用于内部生成受限的 owner 连接凭据，不回传到浏览器。

远程实例或手动接入放在“手动连接/远程DSH”高级设置。地址和认证需要属于同一个受管理实例。交互答复需要能够建立 `interactions: answer` 的 owner 连接；仅有旧 cookie 的连接不能据此承诺模型提问和工具确认可用。Windows/macOS 的本机自动鉴权尚无本实现的验收保证，可使用明确的高级接入方式。

实现见 [本机发现](../src/host/local-dsh-discovery.ts)、[本机鉴权](../src/adapters/dsh-local-auth.ts) 和 [DSH 端口工厂](../src/adapters/dsh-jsonrpc.ts)。

## 应用方案与实际模型元数据

先保存提供方、模型和人设，再在方案页选择“应用”（按状态也可能显示“应用并启动”）。这一操作保存当前编辑方案并选择启用，再创建一次应用；无更改且已启用的方案不会重复保存。其他页面保留对应应用入口。宿主读取保存后的实际 revision，自动识别 DSH 静态配置层、目标路由和模型元数据，生成受管理配置；用户不需要重新填写内部路径或已经可读的模型容量。

应用过程核对保存 revision、文件来源和备份，保留非托管内容。配置包含实际支持的推理档位、输入模态及上下文/输出保留参数；缺少或矛盾的模型元数据会阻止相关应用或迁移，不从模型名称猜测能力。独立助手使用独立命名空间的目标预设，在保存并启用助手时自动配置和核验；需要重新加载时由本机维护服务处理。

思考强度查询、聊天应用和助手配置共用供应商模型能力缓存，命中时不重复发现 DSH 或扫描配置。首次读取及显式刷新先核对 DSH 原始声明，未取得完整声明时读取所选供应商的 `/models` 元数据。只有完整、可解析的模型声明才缓存；仅包含模型名称的列表不证明思考档位或容量。DSH 声明在相同规范服务地址和模型标识下优先匹配所选 API 类型；没有该类型时使用其余一致的声明，沿用原有来源选择规则。框架生成的会话路由不作为原始模型容量来源。

缓存独立持久化，不改变供应商目录版本，不要求重启聊天；供应商页提供逐模型刷新、手动填写和清除。供应商 `/models` 只列名称时，在“能力 → 手动填写”保存容量、输入模态与思考映射；例如 `reasoningEfforts: { low: low, high: high, max: xhigh }`。Key 用于鉴权，不用于推断能力。手动值标记为 `manual` 并优先使用，自动刷新和迟到读取不能覆盖，自动缓存容量回收也不淘汰手动声明；需手动编辑或清除。缓存包括思考档位到请求参数的映射、窗口、输出上限和已声明的输入模态，按供应商、规范服务地址、API、模型和凭据指纹隔离，重启后仍可复用。刷新失败保留既有记录，连接身份变化不借用其他模型或地址的记录。聊天应用保留当前已保存的输出预算且不超过新模型的最大输出，其他模型能力完整使用新声明；旧部署全局能力不作为新模型的缺失声明回退。

同一地址存在历史生成路由时，优先使用与已保存供应商标识、地址、API 和模型均匹配的原始声明，避免把旧会话窗口混入模型真实容量；找不到此声明时才按上述规则核对其余候选。

浏览器只提交一个应用 operation，后台按持久阶段执行停止、准备、应用、会话衔接和启动。关闭页面后可只读查找原操作。丢失回包时按原 operationId 核对；不会因轮询或重新打开页面再次提交相同应用。

`pending_reload` 表示配置已经写入、尚未核验被 DSH 加载。正常应用会在有界时间内只读等待加载，核验通过后继续原操作；仍未加载时显示等待核对。现有会话需要加载新提示词时，受控本机宿主会先核验排空与独占归属，再通过已配置管理器重启 DSH；原 sessionId、代次与历史保留。远程或未受管实例需要按缺失原因维护，不能将未加载当作成功。必要时按实例运维方式使配置加载，再明确选择“核对并继续更新”：原配置和实际加载证据通过后，只沿原操作继续会话衔接与启动，不再次写入或应用。文件来源和预设核验成功仍不证明模型服务可调用，也不证明凭据当前加载值的身份一致；控制台保留这些未验证项。

启动检查只核对连接与配置，不发送模型请求。当前原生状态的 `modelExecutionVerified` 固定为 `false`，表达这一检查范围，不会在后台等待一次模型核验后自动变更。实际请求与回复结果请在会话及执行记录中核对。

## 明确重启本机 DSH

普通只读生效检查不重启 DSH。明确应用聊天方案或人设时，已有会话需要加载新提示词会调用受控本机重载；保存并启用助手时也可能触发加载。需要单独维护时，宿主可提供 `/api/chat/dsh/restart`：GET 只读返回可用性及原操作；POST 携带新的 `operationId` 和当前八份 `revisions`，建立持久维护操作。服务先停止并排空聊天，再重启已确认归属的本机 DSH，核验连接与配置，最后按原运行意图恢复聊天；已有待加载应用则核对并继续原应用，不重复 apply。没有待续行应用时，原来停止的聊天保持停止；已有等待加载的应用按原更新意图继续。维护完成提示不根据 `wasRunning` 推测聊天最终状态，会话历史保留。

当前实际进程适配器通过服务端配置的本框架 `ops/qqbridge-framework` 管理入口，读取其 `describe --json` 实例标识，并核验文件权限、归属及 DSH 凭据目录与自动发现目标一致；原管理器保持兼容识别。浏览器不能指定命令或参数。本机实例必须能被识别并核验进程归属；进程缺失、完全宕机无法识别目标时，页面说明需先恢复服务，不承诺用重启入口盲目启动。远程 DSH、未配置管理器、目标不匹配、其他账号仍在使用同一实例或存在未排空工作时，入口不可用或拒绝维护。

重启响应丢失或进程中断时，保留原操作；查询原 ID 或明确 POST `/api/chat/dsh/restart/reconcile`，body 为 `{ "operationId": "<原 UUID>" }`。核对不会再次执行 restart；证据允许时只继续验证与恢复，证据不足时保持未知。`restartExecutionVerified` 只记录重启命令是否已确认执行，不代表模型调用成功。 普通空查询不会解除未知状态；明确核对证实未受理并原子封存旧 ID 后，才允许新的明确重启，迟到旧请求保持拒绝。

## 工具、媒体与 QQ 交互

框架工具通过受控的 SDK projection lease 安装到具体 session/generation。每次调用关联当前 execution、requestId、真实 SDK claim 和原 QQ 来源，再经功能事件及 policy 执行。模型输入不能指定可信来源或扩大 scope。工具使用会话白名单；移除会话后，实际调用会被拒绝。

框架会话的工具租约同时精简重复的旧桥工具：收件轮询、最近消息、提示词读取、普通回复、消息图片读取、唤醒配置与旧连接状态由现有宿主链路负责。这些工具仍保留全局注册，只在当前框架会话中隐藏；撤销租约时恢复，不改动其他预设、插件安装或授权。搜索、绘图以及其他独立扩展工具继续按原注册方式提供。精简减少后续模型请求中的工具定义，已有会话历史不因此删除，实际 token 用量以模型回报为准。

`qbf_work_start` 是调用已配置助手模型的入口，工具说明附带已保存的助手称呼与模型。助手设置变化时，下一次提交更新工具定义；描述未变化时复用原租约，不在每轮聊天正文重复注入工作说明。聊天侧的文件访问限制不代表助手拥有相同限制，执行仍以助手实际工具和宿主授权为准。助手的文字结果自动回到原 QQ 会话；文件路径文字本身不是附件，只有实际 SDK 附件经过登记后才能按附件回传。

DSH 原有工具清单单独核验。检查时只排除当前框架 lease 实际安装的工具名，不按任意名称前缀豁免其他工具。观察到外部工具清单不表示本框架核验了该工具的具体外部动作权限。

入站图片、音频、文件和合并转发先登记为所属会话的 opaque 资源；不会把原始 URL、本机路径或任意协议数据作为模型已读内容。媒体读取核验当前会话白名单与后端能力：

| 内容 | 当前读取方式与限制 |
| --- | --- |
| 图片 | 当前消息最多四张图片随原生 `session/prompt` 用户附件一次提交，每张按需编码到 160 KiB，内容 JSON 上限 960 KiB。只附当前消息，历史图片不重复添加；下载最多 8 MiB，失败时保留资源引用供按需读取。DSH 负责模型图片准入；按需工具读取仍使用 `ImageBlock`，图片编码上限 383 KiB、工具回包上限 512 KiB。 |
| 文件 | 提供有界、有效 UTF-8 正文；二进制文件或超限文件明确不可读，不将 `FileBlock` 当成已理解正文。 |
| 音频 | 宿主可注入受控转录器；默认未配置时明确 `contentRead=false`，不会声称听懂。 |
| 合并转发 | 按明确读取动作展开有界节点；节点自述 sender 不作为当前 QQ 身份或主人证明。 |

转发节点中的图片沿用所属会话的媒体登记与读取链路。图片优先下载协议消息已提供的登记地址，不依赖协议端按文件名查找普通消息缓存；地址失效或下载暂时失败时，再通过 `get_image` 查询。两条路径共用总读取期限、地址校验和大小上限，拒绝重定向及未信任的内网地址；模型只能传入当前会话的资源标识，不能指定下载地址。

协议服务器未实现所需读取动作时，读取会失败并保留原因，不承诺所有 OneBot 实现都支持相同文件接口。媒体输出消费已登记资源；普通消息保留真实 `message_id`，独立文件上传保留真实文件上传回执，不伪造 QQ 消息 ID。结果未知不自动重发。

模型提问发到所属 QQ 会话，主人的答复回送 SDK。外部工具确认由宿主核对会话、账号、代数、期限和本轮真实来源，主人请求自动允许，非主人请求自动拒绝。独立工作子会话的提问也映射回其可信父 QQ 会话。控制台仅显示只读状态，不提供模型答复或工具批准入口。

## 独立工作通道

工作通道默认停用，启用后使用明确的助手目标，并核验会话白名单和真实主人来源。当前后端使用 SDK 可续接子代理，子会话不自动继承父会话上下文；任务输入由宿主按范围组织。目标 provider、model、reasoning 和 agent preset 来自已核验部署，不借用聊天模型名称推断另一后端可用。

开始前先持久记录任务及子会话绑定，再执行一次实际启动。结果、投递状态和关联证据分别持久化；结果读取与列表不会启动任务。追加和停止走受控 `followup` / `interrupt`，保持原父会话、generation 和固定 child。跨进程恢复只读核对既有工作，不重放 `start`，结果未知时也不自动补发。

独立工作会采集子代理自然产生的公开中间文字，不要求助手专门报告进度，也不采集思考过程、工具参数或执行日志。快照的可选 `progress` 最多保留最近八条、合计 8000 字符；每条包含稳定 `id`、时间 `at` 和 `text`。终态正文通过最终结果通道交付，不重复当作进展。跨进程只读恢复不重新播报历史进展。

进展和最终文字作为宿主观察送回原父聊天，由当前人设决定自然表达；纯计划或重复进展可以静默。首次进展合并等待三秒，同一会话后续进展至少间隔二十秒，最终结果优先；父聊天忙碌或已有 QQ 输入排队时先等待。转述轮使用普通模型、发送及用量链路，额外模型用量正常入账。反馈不是主人消息，不继承主人权限，也不构成新工作授权。原会话、代数、任务或主人发生变化时不向新会话投递。

最终附件继续按实际资源独立发送，文字转述失败不阻止合法附件交付，但整项投递不能因此记为全部成功；文字不回退为直接粘贴子代理原文。每次反馈有持久去重记录，结果未知不自动重发；已确认与明确拒绝的反馈记录七天后过期。最终投递仍受原工作期限及最多两分钟的交付时限约束，文字转述本身最多等待九十秒。

独立工作快照同时返回已结束子会话轮次的真实用量元数据，仅包含 turn、step、时间、provider/model 与 token/cache 计数，不包含正文或 replay state。这些记录随工作 journal 持久保存，再以原 QQ 会话和实际 child session 身份幂等进入 `native-usage.turns`，冷读取不重新调用模型；未报告的计数保留未知。

SDK 图片和文件结果通过受控附件分页读取、注册为框架资源后投递；读取有单页及总量上限。后端缺少 subagent、continuation 或持久查询能力时会明确不可用。真实主人准入的助手工作使用 `fullAccess: true`：插件在子会话首轮前核验已持久保留的工作绑定与真实父级、模型，在子会话自己的官方权限服务中设置并读回 `danger-full-access`（全本机文件与命令、审批 `never`）。普通聊天与父会话权限不变；权限服务或准确预设不可用时拒绝启动。

## 原会话配置更新与执行恢复

日常配置更新复用原受管预设 ID；有持久会话时重新加载本机 DSH，让原会话恢复时挂载最新提示词及容量设置。模型与思考强度通过 `session/selectModel` 在原会话下一次提交前设置，每次运行对同一会话只配置一次。框架不扫描历史媒体、不调用 fork、不改变 sessionId 或 generation。实际模型能力仍从 DSH 元数据核对。

`forkPreview` / `forkWithPreset` 仅保留给显式历史迁移及未知执行恢复，不作为日常配置应用步骤。

迁移要求原执行、收件队列、子工作和外部副作用均满足静止条件。能力范围、工具/插件结构和其他不支持的配置变化仍可能阻止迁移。未知状态不通过清空上下文解决；旧 session ID 保留归属，不能换个会话复用。丢失 fork 回包时，只读检查原请求，不创建第二个 fork。

连接中断、事件序列缺口或插件 epoch 改变会影响证据可信度。当前 session follow 不自动重连并继续未知执行。管理对账读取实际 SDK claim/turn/checkpoint，只记录已核验结果；它不会重新请求模型、取消、发送 QQ 回复或补发旧 final。插件 claim 表示“收件已认领”，不是任务已完成；claim 窗口有界，插件声明 `durableReceipts: false`。

取消结果未知的旧执行仍保留风险证据。只有实际终态证明和其他副作用条件满足时，才允许明确预览、提交新地址恢复；提交丢回包仍沿原 ID/revision 核对。恢复完成后要求显式重启，再接收新消息。证据不足时保持阻断，并给出原因。

连接、执行、工具和工作事件以版本化元数据观察，包含可信关联标识，不包含完整消息或凭据。读取使用有界游标与过滤器；epoch/retention 缺口和订阅背压都有显式结果，不把丢事件视为连续成功。

```sh
npm --prefix packages/dsh-bridge-plugin run check

QQ_FRAMEWORK_DSH_PORT_MODULE="$PWD/src/adapters/dsh-jsonrpc.ts" npm --prefix packages/dsh-bridge-plugin run test:framework

```

当前完整验收包含插件单元 8 项、实际框架端口与官方 SDK 集成 10 项、tarball 隔离安装 2 项，另有默认 native HTTP/WS、迁移、恢复、交互、媒体和工作测试。准确轮次、耗时和失败修复记录见 [验收记录](VALIDATION.md)。有限版本上的通过结果不代表其他 SDK 版本、协议服务或模型都具备相同能力。
