# 管理工作台：独立能力与可选兼容接入

管理工作台是 framework 的中文配置界面，提供日间、夜间与跟随系统三种显示模式。它可以在本机独立预览框架状态，也可以在部署方显式接入协议 gateway、agent 服务或现有 QQ 桥接项目后管理对应配置。

工作台不是完整聊天宿主。它不会自动发现 QQ 账号、OneBot 服务、模型、agent session、插件或业务状态；仅启动界面也不会收发真实消息。框架提供共享 UI 范式，不继续为具体业务包内置页面。新增页面和 API 必须作为可信源码审核、构建并显式接线，不会从 QQ 消息、模型输出或任意目录动态加载代码，也没有插件自动注册机制。

仓库目前自带框架内核、协议适配器和 HTTP gateway，但尚未提供安装后即可完成 QQ 收发、agent 会话、模型调用与业务功能的完整聊天成品。完整聊天仍需可信宿主装配；现有线上聊天在完成并验收迁移前继续由原桥接部署负责，不能因为独立预览或 gateway 启动成功就宣称已经替换。

本项目参考原开源项目 [Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge)，但属于独立重建，不是原项目的官方管理端。来源与许可归属见仓库根目录的 [NOTICE](../NOTICE.md)。

## 1. 独立初始化并启动

新项目不需要安装 qq-bridge。首次使用运行：

```sh
npm ci
npm run cli -- init
npm start
```

`init` 只需执行一次。它创建 `runtime/admin/config.json`、`runtime/gateway/config.json` 和 `runtime/gateway/gateway.token`，并为 gateway SQLite 存储预留同一私有目录。目录权限为 `0700`、文件权限为 `0600`；随机 gateway token 不在 CLI 输出或响应中回显，已有目标文件存在时拒绝覆盖。

`npm start` 是 `npm run cli -- start` 的快捷入口，会自动完成所需构建并启动 gateway、管理 API 与静态界面。默认访问 `http://127.0.0.1:3210/`。管理员令牌不由 CLI 创建或返回，只在首次网页初始化时生成到 `runtime/admin/gateway-admin.token` 私有文件。

## 2. 独立模式的配置与边界

独立配置默认使用以下拒绝式状态：

- 外部 OneBot HTTP upstream 为 `http://127.0.0.1:3000`，需要使用者自行部署、认证并在界面中按实际环境修改。
- framework gateway 只监听 `127.0.0.1:3131`；`init --host` 和 `--port` 只修改管理服务监听，不修改 gateway 或 upstream 端口。
- 允许发送范围初始为空，所有带群聊或私聊目标的发送都会被拒绝。使用“访问范围 → 消息发送范围 → 允许发送的会话”逐行填写 `group:群号` 或 `private:QQ号`；保存使用 CAS 并旋转授权版本，空列表始终表示全部拒绝。
- `budget=false` 只关闭额外次数/期限预算，不会绕过空发送范围、认证或 capability 授权。
- gateway 请求超时默认 60000 毫秒。

该独立模式没有 OneBot WebSocket 或其他入站、DSH、agent session、模型和业务功能，只是 OneBot HTTP egress 兼容层与管理界面。外部 OneBot 服务及其协议认证仍由使用者部署。完整 QQ 聊天需要另行装配可信宿主；当前线上聊天在完成迁移验收前仍由原桥接部署负责。

已经有通过严格校验的私有 gateway 配置时，可使用高级入口：

```sh
npm run cli -- init --gateway-config /path/to/private-gateway.json
npm start
```

`init`、`start` 和 `status` 的管理配置路径依次选择显式 `--config`、`QQ_AGENT_CONFIG`、`runtime/admin/config.json`。普通初始化和启动不安装或要求 Playwright。

只需界面/API 时可运行 `npm run cli -- start --admin-only`，但仍必须已有有效管理配置；该选项不会创建聊天宿主。

gateway 必须使用固定非零端口。目标端口已有服务时，CLI 只在认证健康检查返回完全匹配的配置 revision 时复用；否则拒绝启动，不抢占端口或停止其他服务。退出时只关闭本次 CLI 自己启动的进程。

管理配置、gateway 配置与管理员令牌文件必须是私有普通文件，不能是符号链接。首次网页访问才生成管理员令牌；CLI 不创建或打印令牌值。不要把真实路径、账号、配置、人设、管理员令牌或协议 API token 写入仓库、聊天、截图或 URL。

## 3. 接入现有 qq-bridge（可选）

只有迁移或兼容现有部署时才提供桥接项目目录：

```sh
npm run cli -- init --bridge-dir /path/to/qq-bridge
npm start
```

初始化只准备 framework 使用的私有 gateway 与管理配置，不激活接入、不修改现有桥接端点，也不覆盖已有配置。需要由界面触发受控应用时，可在首次初始化命令末尾追加 `--service-manager /absolute/path/to/trusted-manager`；未提供时 CLI 不猜测服务管理方式。该程序必须是已存在、可信、不可由组或其他用户写入的普通可执行文件，且不能是符号链接。

这条兼容路径不会迁移或替换现有部署的 OneBot ingress、agent runtime、session、插件、工具审批和业务状态。停用原后端后，这些能力不会自动出现在 framework 中。

## 4. 首次访问

首次网页访问会自动创建一个随机、固定的私有管理员令牌文件，并在登录窗口显示文件路径。用户在本机读取令牌并完成登录校验；浏览器把令牌作为 Bearer 提交到 `POST /api/auth/login`，服务端验证成功后签发访问会话。提交后前端立即清空表单内存，不回显，也不把令牌写入 `localStorage`、`sessionStorage`、cookie、URL、日志或其他持久状态。

访问会话使用同源 `HttpOnly`、`SameSite=Strict`、`Path=/api` cookie。普通浏览器 API 请求只携带该 cookie，不发送管理员 `Authorization`。刷新或重新打开同一站点时，页面通过 `GET /api/auth/session` 恢复会话；响应中的 `expiresAt` 是 Unix 毫秒数。会话默认采用七天绝对有效期，不因持续使用而无限延长；可在“运行设置 → 访问会话 → 访问令牌有效期（毫秒）”中调整，最小 300000 毫秒，最大 30 天。对应管理配置字段为 `accessSessionTtlMs`；保存后需重启管理服务生效，而重启本身会使全部现有会话失效。用户可通过 `POST /api/auth/logout` 主动注销当前会话，服务端必须立即撤销会话并清除 cookie。

管理员令牌、访问会话与协议 API token 是三类不同对象：管理员令牌用于换取管理访问会话，也可供既有受控脚本继续直接使用 Bearer 认证；访问会话只授权当前管理工作台；gateway、OneBot upstream 或其他协议 API token 只用于对应机器接口，不能粘贴到管理登录框或由页面代为保存。管理员令牌文件随后持续复用，不会在每次访问时变化。初始化标记已经存在而令牌文件丢失时，工作台应要求恢复，不会静默生成新身份；轮换管理员令牌也不得改动协议 API token。

监听 `0.0.0.0` 或 `::` 时，浏览器应访问机器的实际地址和配置端口，而不是通配监听地址。页面 API 始终使用同源相对地址，没有内置固定 IP 或端口。

## 5. 六个中文页面

| 页面 | 当前能力 |
| --- | --- |
| 概览 | 查看已接入 gateway、agent 服务与当前进程范围内的发送和异常摘要。 |
| 人设与形象 | 接入聊天宿主后列出、新建、编辑、启用或停用人设；未接入时显示“尚未接入聊天宿主”，不误报旧管理 API 错误。 |
| 功能与触发 | 编辑可信后端通过现有配置 schema 暴露的功能开关、触发条件、发送节奏和媒体限制；关闭功能不会自动清空其保留配置。 |
| 访问范围 | 编辑允许/拒绝的群聊和私聊目标及管理员账号，并在保存前同步兼容网关目标。 |
| 模型与回复 | 接入聊天宿主后编辑 agent、模型连接、联网搜索、价格与回复设置；未接入时显示“尚未接入聊天宿主”。 |
| 运行设置 | 管理发送预算、gateway 容量、管理端监听地址，以及“访问会话”分组中的“访问令牌有效期（毫秒）”。 |

页面只展示后端实际提供的字段。秘密值只显示“已配置/未配置”，留空保存表示保留原值；代码回调、运行对象和未接入能力不会伪装成可编辑设置。

这六页是框架与兼容接线的基础管理面，不是业务包 UI 目录。具体业务包没有专用页面属于预期边界，不应列为框架未完成事项；需要时由业务方或 AI 按 `UI.md` 的共享范式编写可信页面并显式接线。

每个页面提供用于定位当前页面结构的本页目录：桌面端固定在内容右侧，移动端可折叠。目录不提供搜索。选择目录项会展开目标所在的折叠分组，再滚动并聚焦目标；该操作不改变 URL、页面路由、表单草稿或未保存状态。

标题栏提供文档站式全局搜索。按 `Ctrl/⌘K` 打开搜索窗口，可查询页面、分组和字段名称；选择结果后导航到目标，并在页面渲染后展开折叠分组、滚动和聚焦。跨页面时仍必须经过未保存草稿确认，搜索本身不得保存、重置或改写草稿。搜索不读取输入控件当前值、令牌、秘密、人设正文、消息正文或错误详情。页面不再保留重复的页内搜索或内部分组筛选。

同一功能域的运行模式必须互斥选择，界面不会用多个可同时开启的开关表示互斥模式。功能总开关关闭后，其未修改依赖配置从页面和本页目录中隐藏，并按注册元数据的可用状态退出全局搜索结果，但已保存值不会因此被清空；再次开启后恢复显示。若依赖字段已有未保存草稿，页面会暂时保留并标明停用状态，供用户保存或撤销。需要核对保留值时，可显式开启“显示停用配置”；默认仍保持隐藏。隐藏配置不等于删除、应用或撤销现有运行状态。

## 6. 保存、应用与未知结果

页面对操作结果作以下区分：

- **未保存**：改动只在浏览器表单中，离开页面前会提示。
- **已保存，尚未应用**：新 revision 已原子写入私有配置文件，但运行中的服务还没有重载。此状态不等于线上行为已经改变。
- **已应用**：服务管理程序已完成对应组件重启，且应用流程完成必要校验。页面随后重新读取状态。
- **重启已受理，需要重连**：管理端自身的重启请求已经提交；这不是“已应用”的确认。应使用页面给出的新地址，或用实际主机地址与新端口重新打开页面。服务重启会使访问会话失效，因此需要用管理员令牌重新登录。
- **结果待确认 / `unknown`**：请求可能已经开始，但管理端无法确认最终结果。不要自动重试或重复写入；先重新读取配置、检查 revision 和健康状态，再决定是否操作。

兼容网关未显式配置 `timeoutMs` 时，单次请求默认超时为 60 秒。GET 超时可以重新读取；POST 超时仍按“结果待确认”处理，不能因为客户端停止等待就假定后端没有开始。

并发修改会返回冲突，页面要求重新载入后再编辑。保存和应用是两个动作；没有接入受信任服务管理程序时，页面只负责保存，部署方需按自己的服务管理方式重载组件。

切换页面或重新打开工作台后，仍可应用当前保存的配置，不必为了重新显示应用按钮而再次修改。初次载入只确认已读取配置文件，不推断运行中的服务已经重载。

## 7. 预算与访问范围

“启用发送预算”是独立开关：

- 关闭时不执行发送次数和授权期限限制，但保留已填写的次数与时间。
- 再次开启时恢复使用这些保留值；未填写的限制项仍表示不限制。
- 切换预算或修改预算值并保存时，管理端会自动生成新的 `authorizationVersion`；应用网关后建立新一代授权，不把普通重启当作自动充值。
- 兼容网关请求超时默认 60 秒；超时、并发、请求体和持久记录上限都是健壮性边界，不随预算关闭而失效。

允许群聊和允许私聊可以同时为空。这是有效的拒绝式配置：同步后兼容网关的 `allowedConversations` 为零项，所有带群聊或私聊目标的读写和发送请求都会被拒绝，而不是解释为“允许全部”。拒绝名单仍优先排除同名目标。

接入现有部署时，访问范围保存会先同步并应用兼容 gateway，再写入现有部署的允许列表；同步失败时后续设置不会保存。该流程只覆盖经过 HTTP gateway 的目标，不能约束绕过它的其他协议调用。

## 8. 安全与排障

- 普通 HTTP 不加密管理员令牌或访问会话。非回环监听只适用于可信网络；跨不可信网络应使用 HTTPS 反向代理或受控隧道。
- 登录 `401` 表示应检查管理员令牌，而不是 gateway、OneBot 或其他协议 API token。其他 API 返回 `401` 时应先确认访问会话是否过期或因服务重启失效。
- 首次访问无法初始化时，检查管理员令牌目录是否为私有规范目录，以及现有文件是否满足私有普通文件要求。
- 管理员令牌只提交到登录接口；普通管理 API 使用 `HttpOnly` 访问会话 cookie。七天绝对期限到达或服务重启后，旧会话不能继续访问。
- 普通管理 API 返回 `401` 或 `403` 时，页面清除前端连接状态并返回登录界面；网络失败不擅自注销会话，应保留状态并提供重试。
- 有未保存表单时选择退出，取消确认不会调用注销接口；确认离开后才执行 `POST /api/auth/logout`。只有注销成功或收到 `401` / `403` 才清除连接态，网络错误保留会话并提示重试，不能宣称已经撤销。
- 端口占用时修改 `host` / `port`；程序不会夺占端口或静默切换地址。
- gateway 不可用时运行它自身的认证健康检查。工作台不会补发 `unknown` 消息、创建替代 agent session 或自动接管其他协议流量。
- 全局搜索只使用已审核的页面、分组和字段标签元数据，找不到输入内容、人设正文、消息正文或秘密是预期的安全行为。目录与搜索定位不会保存、应用或重置当前草稿。

## 9. 页面扩展与发布核对

管理 UI 扩展属于部署代码变更，不是聊天中的配置操作。发布前应完成以下核对：

1. 审核页面源码、响应校验、秘密处理和服务端管理路由，确认普通消息或模型输出不能决定要加载的代码、路径或路由。
2. 在可信装配根中显式注册页面、安全搜索元数据和固定管理 API；目录、搜索、表单状态和主题必须复用框架共享范式。具体组件接口见技术文档 `UI.md`，不作为普通使用者配置项展示。
3. 运行按范围的类型检查、构建和浏览器验收。`npm run build` 编译 TypeScript，并由 Vite 产出管理端的固定 JS/CSS 静态资源。
4. 核对本页目录和标题栏全局搜索在桌面、移动端及键盘操作下可用；`Ctrl/⌘K` 能打开搜索，跨页结果遵守未保存草稿确认，折叠分组会先展开再定位，输入值、秘密与正文不会进入索引。
5. 部署审核后的构建产物及匹配的服务端代码。管理服务只提供固定静态入口和显式安装的有限 API 路由，不会扫描目录或自动发现插件。

具体 TSX 页面范式和完整验收清单见[管理界面与扩展约定](UI.md)。某个业务页面尚未编写不表示框架本身未完成；业务方应按该范式在自己的可信 composition 中实现和验收。

以下命令用于开发回归，不是首次启动步骤，也不读取当前管理配置执行线上健康检查：

```sh
npm run cli -- build
npm run cli -- test

```
