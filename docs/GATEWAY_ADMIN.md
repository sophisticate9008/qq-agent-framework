# 管理工作台：部署与使用

管理工作台是面向兼容部署的中文配置界面。页面由 React、shadcn/ui（Base UI）、Tailwind CSS 和 Vite 构建，提供日间、夜间与跟随系统三种显示模式。它可以编辑 framework 网关配置，并在接入旧 bridge 管理接口后编辑人设、功能、访问范围和模型设置。

工作台不会把 HTTP 出站兼容网关变成完整宿主：旧 OneBot WebSocket ingress、DSH runtime、现有 session、插件、工具审批和业务状态仍由原部署负责。停用原后端后，这些能力不会自动迁入 framework。

## 1. 创建管理配置

先完成[旧 OneBot HTTP 出站兼容网关](LEGACY_GATEWAY.md)的私有配置并确认网关可用。以下命令只创建管理配置，不创建或打印管理令牌：

```sh
npm ci
npm run build

export PRIVATE_GATEWAY_CONFIG=/path/to/private/gateway.json
export PRIVATE_ADMIN_CONFIG=/path/to/private/admin.json

node scripts/configure-gateway-admin.ts \
  --config "$PRIVATE_ADMIN_CONFIG" \
  --gateway-config "$PRIVATE_GATEWAY_CONFIG"
```

默认监听 `127.0.0.1:3210`。地址和端口不是写死值，可在初始化时指定：

```sh
node scripts/configure-gateway-admin.ts \
  --config "$PRIVATE_ADMIN_CONFIG" \
  --gateway-config "$PRIVATE_GATEWAY_CONFIG" \
  --host 0.0.0.0 \
  --port 8080
```

`--host` 接受 `localhost` 或明确的 IPv4/IPv6 地址，`--port` 接受可用的非零端口。`--token-file` 可指定管理令牌文件；省略时使用管理配置同目录下的 `gateway-admin.token`。初始化工具不会覆盖已有管理配置，也不会轮换已有令牌。

管理配置支持以下字段：

| 字段 | 用途 |
| --- | --- |
| `host` | 工作台监听地址。 |
| `port` | 工作台监听端口，与 OneBot 协议端口分开。 |
| `tokenFile` | 工作台独立认证令牌文件。首次网页访问时创建。 |
| `gatewayConfiguration` | 兼容网关私有配置文件。 |
| `legacyRoot` | 可选；原 bridge 的私有根目录。配置后开放人设、访问范围、模型及旧 bridge 设置。 |
| `serviceManager` | 可选；受信任的服务管理程序。配置后页面可以应用设置并请求重启对应组件。 |

相对路径以管理配置所在目录解析。要使用完整六页配置和“保存后应用”，部署方需在私有管理配置中补充适合本机的 `legacyRoot` 与 `serviceManager`；不配置时页面仍可打开，但依赖旧 bridge 的区域不可用，保存后的服务应用也需由管理员在页面外完成。

配置文件与令牌文件必须是私有普通文件，不得是符号链接；令牌目录需为仅当前用户可访问的规范目录。不要把真实路径、账号、配置、人设或令牌写入仓库、聊天、截图或 URL。

## 2. 启动与首次访问

```sh
node scripts/gateway-admin.ts --config "$PRIVATE_ADMIN_CONFIG"
```

另一个终端可查看地址和健康状态：

```sh
node scripts/gateway-admin.ts --config "$PRIVATE_ADMIN_CONFIG" --address
node scripts/gateway-admin.ts --config "$PRIVATE_ADMIN_CONFIG" --health
```

首次网页访问会自动创建一个随机、固定的私有管理令牌文件，并在连接窗口显示该文件路径。用户只需在本机打开显示的文件，把令牌粘贴到页面；不需要预先运行长命令生成令牌。页面不会显示令牌值，也不会把令牌写入本地存储或会话存储，刷新或关闭页面后需要重新输入。

自动初始化只执行一次：令牌文件随后持续复用，不会在每次访问时变化。初始化标记已经存在而令牌文件丢失时，工作台会要求恢复该文件，不会静默生成新身份。需要轮换时，应由部署方用既有密钥管理流程写入新的私有文件、更新 `tokenFile` 并重启管理端；不要改动 OneBot 调用方使用的协议令牌。

监听 `0.0.0.0` 或 `::` 时，浏览器应访问机器的实际地址和配置端口，而不是通配监听地址。页面 API 始终使用同源相对地址，没有内置固定 IP 或端口。

## 3. 六个中文页面

| 页面 | 当前能力 |
| --- | --- |
| 概览 | 查看兼容网关、旧 bridge、DSH 与 SnowLuma 的可用状态，以及当前进程范围内的发送和异常摘要。 |
| 人设与形象 | 列出、新建并实际编辑人设正文；可启用或停用当前人设。现有人设名称不可直接改名，保存不会重置已有会话。 |
| 功能与触发 | 编辑旧 bridge 暴露的功能开关、触发条件、发送节奏和媒体限制；关闭功能不会自动清空其保留配置。 |
| 访问范围 | 编辑允许/拒绝的群聊和私聊目标及管理员账号，并在保存前同步兼容网关目标。 |
| 模型与回复 | 调整旧 DSH 的思考强度，并编辑模型连接、联网搜索、价格与回复相关设置。 |
| 运行设置 | 管理发送预算、网关容量、管理端监听地址和其他运行参数。 |

页面只展示后端实际提供的字段。秘密值只显示“已配置/未配置”，留空保存表示保留原值；代码回调、运行对象和未接入能力不会伪装成可编辑设置。

## 4. 保存、应用与未知结果

页面对操作结果作以下区分：

- **未保存**：改动只在浏览器表单中，离开页面前会提示。
- **已保存，尚未应用**：新 revision 已原子写入私有配置文件，但运行中的服务还没有重载。此状态不等于线上行为已经改变。
- **已应用**：服务管理程序已完成对应组件重启，且应用流程完成必要校验。页面随后重新读取状态。
- **重启已受理，需要重连**：管理端自身的重启请求已经提交；这不是“已应用”的确认。应使用页面给出的新地址，或用实际主机地址与新端口重新打开页面并再次输入令牌。
- **结果待确认 / `unknown`**：请求可能已经开始，但管理端无法确认最终结果。不要自动重试或重复写入；先重新读取配置、检查 revision 和健康状态，再决定是否操作。

并发修改会返回冲突，页面要求重新载入后再编辑。保存和应用是两个动作；没有配置 `serviceManager` 时，页面只负责保存，部署方需按自己的服务管理方式重载组件。

切换页面或重新打开工作台后，仍可应用当前保存的配置，不必为了重新显示应用按钮而再次修改。初次载入只确认已读取配置文件，不推断运行中的服务已经重载。

## 5. 预算与访问范围

“启用发送预算”是独立开关：

- 关闭时不执行发送次数和授权期限限制，但保留已填写的次数与时间。
- 再次开启时恢复使用这些保留值；未填写的限制项仍表示不限制。
- 切换预算或修改预算值并保存时，管理端会自动生成新的 `authorizationVersion`；应用网关后建立新一代授权，不把普通重启当作自动充值。
- 请求超时、并发、请求体和持久记录上限是健壮性边界，不随预算关闭而失效。

允许群聊和允许私聊可以同时为空。这是有效的拒绝式配置：同步后兼容网关的 `allowedConversations` 为零项，所有带群聊或私聊目标的读写和发送请求都会被拒绝，而不是解释为“允许全部”。拒绝名单仍优先排除同名目标。

访问范围保存会先同步并应用兼容网关，再写入旧 bridge 白名单；同步失败时旧 bridge 设置不会保存。该流程只覆盖经过 HTTP compatibility gateway 的目标，不能约束绕过网关的旧 WebSocket 调用。

## 6. 安全与排障

- 普通 HTTP 不加密管理令牌。非回环监听只适用于可信网络；跨不可信网络应使用 HTTPS 反向代理或受控隧道。
- `401` 表示应检查管理令牌文件，而不是 OneBot token 或文件路径。令牌只应在本机读取。
- 首次访问无法初始化时，检查令牌目录是否为私有规范目录，以及现有文件是否满足私有普通文件要求。
- 端口占用时修改 `host` / `port`；程序不会夺占端口或静默切换地址。
- 网关不可用时运行网关自身的 authenticated health 检查。工作台不会补发 `unknown` 消息、创建替代 DSH session 或自动接管旧 WebSocket 流量。
