# GIF 观看与发送

GIF 属于图片，不受“允许观察视频”开关控制。模型需要理解动图时，通过当前会话的媒体读取能力观察抽样画面；不会用第一帧代替整段动画。

读取器使用现有本机图像组件，按照 GIF 的实际帧间隔累计时间，从一轮动画中均匀选取时间点（V1 最多六帧，V2 最多 24 帧）。结果包含真正的图片附件、各帧时间、原始帧数和循环信息。抽样可能遗漏快速变化，不表示每一帧都已查看。单帧 GIF 按普通静态图片处理。

当前输入上限为 8 MiB；V1 抽样图最长边 960 像素，总字节不超过 360 KiB；V2 拼图规格与预算见下文。解码另限制源帧数、像素与处理时间；无法可靠读取动画时间信息时明确报告，不编造时长。GIF 不自动转换成首帧图片塞入每轮输入，按当前对话需要读取。

发送已有 GIF 使用原始字节，观察用的 JPEG 抽样帧不会替换原件。白名单会话可以按现有图片输出方式发送当前会话已登记的 GIF；主人可以委派助手读取获准的本机 GIF 并作为图片附件回传。本机文件访问与聊天身份校验沿用原有规则。

框架确认的是交给协议端的 GIF 字节和协议回执；QQ 客户端是否自动播放仍取决于客户端行为。实际模型模拟使用本地协议捕获，不能当作真实 QQ 已送达。

元数据和抽帧接口参考 [Sharp 元数据文档](https://sharp.pixelplumbing.com/api-input/) 与 [图像输入选项](https://sharp.pixelplumbing.com/api-constructor/)。

## V1/V2 固定画面方案

概览“媒体观察 → 画面方案”与视频共用，默认 V1；模型仍只传媒体句柄。V1 均匀抽取最多六张独立 JPEG。V2 沿实际播放时间均匀选取最多 24 帧并去重，每帧宽高各减半，超大画面继续缩小到每格最长边 960 像素；每四帧拼成一张，按左上、右上、左下、右下读取，末张未使用的格位保持空白。最多六张拼图，每张最多 256 KiB，总共 1.5 MiB，工具线格式最多 3 MiB。返回原动画帧数、循环次数及每格真实显示起始时间；不将拼图替代原 GIF 对外发送。

V2 按四帧一组保留缩小后的 RGB 像素，编码后释放这一组，再处理下一组；保留原 GIF 合成和帧处置语义。原动画仍受 8 MiB、256 帧、单帧 1600 万像素及所有帧合计 6400 万像素限制。每个进程最多一个 GIF 观察，忙时明确返回未读取。V1 总预算 9 秒，V2 总预算 20 秒。均匀抽样可能漏掉短暂动作，减半会减少细节；工具返回的格位、实际时间与空白说明须一同理解。
