# 目标与范围

## 目标

QQ Agent Framework 提供可组合的消息桥接基础件，使宿主可以接入 QQ 协议和外部 agent，并通过独立功能包增加行为，而不把协议细节、会话管理和业务规则耦合在同一个入口中。

框架重点保证：

- 稳定的事件、消息、功能和适配器契约。
- 可解释的功能生命周期、排队、取消和故障隔离。
- 会话身份、持久状态、任务、资源与出站记录可恢复。
- 所有副作用经过明确 capability、作用域和有限预算授权。
- 外部系统返回确认、拒绝或未知时，宿主采用可审计的恢复策略。
- 功能开发、测试和装配可以独立进行，不要求修改协议或调度核心。

## 数据分类

| 类别 | 说明 | 变更方式 |
| --- | --- | --- |
| 人设 | 身份和表达约束 | 发布明确版本 |
| 配置 | 功能参数和运行策略 | 校验后的管理操作 |
| 偏好 | 有来源、作用域和有效期的倾向 | 明确确认或撤销 |
| 状态 | 会话、任务和功能执行进度 | 受控状态转换 |
| 资源 | 可引用的媒体及其元数据 | 资源服务登记与治理 |
| 权限 | 可执行的动作、对象、预算和期限 | 可信宿主授权 |

这些类别不能互相替代。配置、偏好、消息内容或模型输出都不能创建权限；资源标识也不能直接解释为文件系统路径。

## 必要桥接能力

框架面向真实桥接时至少需要以下层次：

1. 协议适配：验证入站请求，规范化消息、提及、回复和资源引用。
2. 会话注册：稳定映射会话与 agent session，并用 epoch 或 generation 防止旧跟随流污染新会话。
3. agent 适配：创建会话、提交消息、跟随结构化事件和协作式取消。
4. 持久存储：带 revision 的条件写入、过期清理和明确关闭语义。
5. 持久任务与出站：记录状态转换、幂等键、发送回执和未知结果的对账入口。
6. 资源目录：只通过受控标识解析媒体，记录类型、来源和生命周期。
7. 宿主恢复：启动时重建会话跟随、任务与出站状态，不把重启等同于安全重放。

每项能力只有在实现、测试并记录限制后，才可从目标升级为可用接口。

## 非目标

- 不重建外部 agent runtime、QQ 协议实现或模型服务。
- 不把业务人格、固定话术或特定内容策略内置到框架核心。
- 不允许普通消息直接安装代码、扩大授权或部署生产版本。
- 不宣称提供不可信插件隔离、外部动作回滚或 exactly-once 交付。
- 不以测试数量、单次基准或演示页面通过代替生产验收。

## 成熟度要求

本地内核、演示适配器和真实集成分别验收。生产使用前还需覆盖身份鉴别、密钥管理、故障恢复、长时间运行、容量、速率限制、数据迁移和运维回滚。
