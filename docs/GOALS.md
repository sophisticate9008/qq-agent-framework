# 独立桥接框架目标

建立日期：2026-10-24。状态：首轮 TypeScript 内核与演示已实现，验收记录见 iterations；尚未生产部署。
“首轮已实现”不是框架整体完成。性能与可靠性必须有独立证据；迭代002开始补齐离线性能基线。

## 用户目标

像游戏引擎一样提供可组合的基础件，使工作 agent 能通过独立功能模块开发各种 QQ 能力，
而不是反复侵入旧 bridge。DSH 是成熟底座，不重建它；独立建设桥接内核及 UI。
旧项目仅提供需求和失败模式参考，既有部署、会话、资产与未提交修改全部保留。

## 分类原则

| 类别 | 内容 | 变化入口 |
| --- | --- | --- |
| 人设 | 身份、背景、性格、表达风格、外貌锚点 | 明确编辑并发布新版本 |
| 能力 | 功能契约、实现、依赖及版本 | 开发、测试、装配 |
| 行为配置 | 触发规则、处理上限、有效期等参数 | 校验后的管理配置 |
| 偏好 | 风格、频率与内容倾向 | 明确确认；临时覆盖有作用域与时效 |
| 运行状态 | 忙闲、冷却、任务、素材与执行进度 | 受控状态转换 |
| 权限 | 操作范围、授权、预算、暂停与撤销 | 可信宿主授权流程 |

固定与动态不是上述分类的替代品。固定定义不能被普通聊天或模型推断改写，但可经明确
工程变更升级；持久偏好与临时偏好分开。不同角色、会话、用户与任务数据不能相互污染。

## 首轮范围

- 无环境副作用的可导入内核；显式功能装配、受控副作用、生命周期与脱敏观测。
- 人设、行为配置、偏好和功能状态独立服务；权限不由这些内容派生。
- 两种不同功能共享内核：对话回应与手动触发提醒；均使用演示适配器。
- 独立管理 UI，回环地址、显式认证，无生产配置或服务连接。
- 完整离线测试、迭代档案、公开仓库发布；不把演示通过写成真实 QQ/DSH 验收。

## 语言与证据要求

- 用户后续明确要求统一 TypeScript；内核、适配器、功能包、UI 逻辑、脚本和测试均用 `.ts`。
- 开启 strict 类型检查，不以改后缀、禁用检查或 `any` 逃逸代替迁移。
- 文档、接口示例和运行命令同步迁移；浏览器使用忽略提交的编译 JavaScript，这是产物不是源码。
- 旧版 JavaScript 原型的测试只作历史证据，不能替代 TS 源码与编译产物的重新验收。
- 每轮记录对象、版本、命令、结果、失败修正、边界与剩余项；真实外部链路没有验收就标未验证。

## 后续路线

1. 稳定内核与分类数据契约，证明两个不同功能可独立安装与停用。
2. 设计持久任务、统一出站恢复、资源/产物与有限重试，验证跨重启语义。
3. 实现最小 QQ 与 DSH 适配器，分别在明确授权下做真实集成验收。
4. 自身形象表达作为功能包：固定参考、轻量审图、最多一次打回、合格旧图兜底、择机发送。
5. 完善开发脚手架、发布恢复和 UI；用不同类型功能检验通用性。

## 工程验收维度

每轮除功能外，还应按影响范围检查吞吐/分位延迟、事件循环进展、队列与并发上限、内存保留、
异常/慢任务/过载、长时间运行及恢复。未测的维度保持未验证，不用测试数量或单次微基准替代。
基准要绑定版本、负载、环境和计量方法；优化不能牺牲授权、数据分类、交付真实性或既有成果。

首轮没有自动定时主动发言，也不启用旧项目已关闭的主动话题或黑话功能。
首轮内存实现不宣称持久化、重启恢复、可靠热更新或不可信插件隔离。
