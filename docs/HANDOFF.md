## 下一轮按顺序推进

1. 明确任务存储/出站恢复协议：accepted、running、unknown、confirmed、failed，不把重新执行当恢复。
2. 建立资源与产物服务：固定人设参考、审核记录、版本适配、有限重试、过期与清理规则。
3. 给工作 agent 独立工程入口：认证主人请求、结构化目标、可写范围、预算、测试、产物和装配权限。
4. 做最小 QQ/DSH 适配器；先用无外部副作用的真实框架组合，再单独核对真实调用授权。
5. 最后实现自身形象表达功能包；各时段/季节仅产生候选，需语境和权限门控。

每项完成时追加：验收对象/版本、命令或操作、实测结果、失败修正、未覆盖范围和下一步。
不要把注册、可发现、可调用、输出可消费、目标端确认合成一个 active 标签。

性能后续项：小时/天级长稳、写状态和历史数据治理、真实QQ/DSH负载、流式模型、完整app/UI大快照、
跨重启恢复与退化性能；均未被本轮短离线测试覆盖。

## 保持不变

- DSH 本身不重建；旧部署、会话、素材、原型与未提交改动不删除、不覆盖。
- 旧主动话题/黑话关闭状态不因新需求恢复；本轮无真实发送/模型调用或生产重启。
- 管理 UI 不接受任意代码、任意路径、模型地址、网关地址或授权扩张。
- 功能是可信代码；没有 JavaScript 沙箱。取消协作式，宿主不能保证强制中断卡死插件。
- 所有运行数据目前在内存；去重有限窗口，重启不是安全的重发理由。
