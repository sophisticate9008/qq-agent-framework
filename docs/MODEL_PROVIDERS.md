# 模型提供方

在侧栏“模型提供方”集中维护连接与模型。聊天方案只引用提供方和模型标识，不重复保存地址或密钥。

## 使用方式

1. 新建提供方，填写方便识别的名称。
2. 选择 OpenAI 兼容或 Anthropic 类型，填写服务地址和 API 密钥。
3. 在该提供方下登记模型的 API 标识及显示名称。
4. 返回“聊天方案”，从下拉列表选择提供方与模型，分别填写群聊、私聊上下文上限。

类型描述连接协议，不是一次连通性检测。当前管理端只保存配置，不会发送测试请求、自动修改外部 DSH 配置或替换现有会话。完整聊天链路未接入时，保存成功不代表模型已可用于聊天。

## 配置与凭据

`GET /api/chat/providers` 返回 `{ revision, providers }`。每项提供方包含：

- `id`：稳定引用标识。
- `name`：显示名称。
- `type`：`openai` 或 `anthropic`。
- `baseUrl`：固定服务地址。
- `enabled`：是否可供新方案选择。
- `apiKeyConfigured`：是否已保存密钥，不包含密钥原值。
- `models`：`{ id, name }` 数组，分别表示实际请求使用的模型标识和显示名称。

`POST /api/chat/providers` 接收完整目录和读取时的 `revision`。写入项不包含 `apiKeyConfigured`；可选 `apiKey` 用于更新密钥，省略或空字符串保留相同提供方标识的已有密钥。只有 `clearApiKey: true` 才清除密钥，不能同时提供新的非空密钥。

地址只允许 HTTPS 或本机回环 HTTP，不允许 URL 内嵌凭据、查询参数或片段。提供方目录内的标识、名称不能重复；每个提供方内部的模型标识、名称也不能重复。模型显示名称留空时，页面使用 API 模型标识。配置使用框架自己的私有文档 `chat-providers.json`，目录权限 `0700`、文件权限 `0600`，文档上限 64 KiB；HTTP 请求另受管理端请求体上限约束。

写入与聊天方案共用目录级写锁、条件更新和原子替换。冲突后先重新读取，结果未知时不自动重试。服务端不从其他项目发现或复制凭据。

## 引用与上下文

新建或修改模型引用时，必须选择目录中已启用的提供方及其已登记模型。已被方案引用的提供方或模型不能直接移除，先修改相关方案；停用引用中的提供方同样需要先处理引用。

已有文档里尚未登记的模型引用保留原值，可以继续编辑方案其他内容；新建、换用或新启用方案时不能借此绕过目录校验。补登记时使用相同引用标识即可，不猜测服务地址或密钥。

每份方案独立保存 `contextLimits: { group, private }`，单位为 token，均为 `1..16777216` 的整数。缺少此字段的旧文档读取时按各 `128000` 解释，不在读取时改写原文件。两项值不是模型窗口探测结果，也不代替实际引擎的裁剪、输出预留和窗口检查。

框架中立的会话定义可以携带这两项限制；实际 agent 接入必须明确应用，或在不支持时拒绝。外部 DSH 仍需使用已核验的部署预设，不能把配置保存伪装成线上上下文限制已经生效。

本地目录标识也不等于外部 DSH 已存在的提供方名。接入方需要明确建立映射和部署配置，不能只保存一个地址便宣称外部引擎已获得该服务或凭据。
