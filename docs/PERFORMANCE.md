# 性能验收方法与限制

状态：迭代002补充。此前58项功能测试与浏览器通过不构成性能验收，更不代表框架整体完成。

## 固定对象

基线为公开提交 `0bdf2a5ba839116c0fc9d91cb3ba5c28fa6046fe`，不是当前工作树的口头快照。
用同一组 TypeScript 脚本、同机 Node24、新鲜进程对比基线与候选；BENCH_ROOT 指定基线源码根目录。
不读取生产配置、不使用真实 QQ/模型、不把模型/网关耗时计为纯内核性能。
保持其他服务运行，不以清空机器或关闭生产服务换取漂亮数字。绝对时延受共享主机争用影响。

## 工作负载

| 脚本 | 负载 | 核查重点 |
| --- | --- | --- |
| bench-core.ts | 200次预热、2000次事件；0/100/1000个无关功能 | 端到端事件延迟、吞吐、CPU、定时器进展、状态分配 |
| bench-context.ts | 10/1000/10000条偏好，命中1条或全部同作用域 | 分层解析随无关数据增长的成本；最坏命中成本仍需报告 |
| bench-policy.ts | 10/1000/10000条授权；同tuple全部耗尽 | reserve+begin性能；错误码与预算语义不得放宽 |
| bench-admin.ts | 500审计+500消息的固定JSON，回环HTTP并发1/16 | 认证请求吞吐、p50/p95/p99、字节、错误；不是完整app构造或UI渲染 |
| bench-soak.ts | 三窗口各4000个新会话、不读取状态；显式GC | 保留对象、无用命名空间、堆趋势；不是长时间泄漏证明 |

主流程正式基准串行执行，三轮交替基线/候选顺序，报告中位数；不把最好的一次作为结论。
偏好正式每场景100次、预热10次；授权1000次、预热最多100次；HTTP每组100次、无预热，报告会明确冷启动影响。
比较吞吐的比值只适用于这一固定负载，不能外推为真实机器人倍速。

## 验收门槛

可重复的正确性门槛进CI，不在共享runner上设置易抖动的绝对微秒门槛：

- 持续立即完成的事件工作会让出事件循环，定时器/IO可在积压完成前进展。
- 默认每64次调度或累计8ms触发让出；不是8ms的硬实时承诺，也不能抢占一次同步处理器。
- 没有使用状态的会话，不产生永久空状态命名空间；事件/出站/审计历史遵守保留上限。
- 默认发送仍全局顺序；显式并行模式不超过宿主上限，同会话有序，等候动作撤销后不触达适配器。
- 过载有明确拒绝，不无限排队；超载/取消/失败仍排空已有动作并释放并发槽位。
- 所有原授权、过期、覆盖顺序、原型键、认证/同源与脱敏回归继续通过。
- 不用缓存过期授权、动态快照或可变偏好来换取吞吐；静态缓存限三条、每条256KiB，生效至服务器重建。

性能数值属于观察性证据，实际结果及源摘要见 `iterations/002-performance.md`，不先宣称达标。

## 运行

```sh
npm run bench:core
npm run bench:context
npm run bench:policy
npm run bench:admin
npm run bench:soak
```

正式对比的参数为 `BENCH_OPS=100 BENCH_WARMUP=10`（context），其他脚本保持默认值。
例如在另一个目录导出基线后运行 `BENCH_ROOT=/absolute/baseline node --expose-gc scripts/bench-core.ts`；
同一脚本不设置 BENCH_ROOT 即测当前源码。三轮分别采用 baseline/candidate、candidate/baseline、baseline/candidate。
并行慢对端场景单独设置 `BENCH_SEND_CONCURRENCY=4 BENCH_ONLY=slow-peer`，不会修改默认发送契约。
`scripts/summarize-performance.ts` 按本轮固定原始文件名汇总，不是通用压测服务；须先生成全部原始结果。

需要比较时设置 BENCH_ROOT；核心/短浸泡使用 --expose-gc，显式GC在计时窗外。
原始结果保存在忽略提交的 runtime/iterations/002；公开摘要包含样本量、分位数、环境、计量方式和限制。
Node性能与内存指标的单位依据官方 perf_hooks 与 process 文档；RSS不等于JS活对象大小。
浏览器回归使用 `FRAMEWORK_ITERATION=002 npm run test:browser`，避免覆盖001的历史证据。

## 尚不能宣称

没有小时/天级长稳、真实多用户模型流、生产QQ/DSH链路、真实网络重试或重启恢复性能证据。
写入的业务状态、授权/偏好历史仍需持久化与生命周期治理；只保证未使用状态不无谓分配，不保证所有内存有界。
合作式让出不能抢占插件的同步死循环；正在调用的慢适配器不支持强制终止。
管理快照仍需构造/复制完整数据；HTTP测试不证明完整app快照或浏览器500条记录渲染性能。
以上是后续工程门槛，不能因本轮离线基准通过就宣布框架完成。
