# 2026-10-29 性能审查与优化

## 测量范围

本机 Linux / Node.js 24.22.1，8 个逻辑 CPU，约 7.3 GiB 内存。通过 `/proc` 的进程 CPU 增量、RSS/PSS、文件描述符与 I/O 观察运行中的框架、DSH 及辅助服务，并分别采集短时 V8 CPU profile。100% CPU 表示一个逻辑核，不是整机占用。

优化前两段各约 30 秒的采样，框架平均占用 66.94% 和 58.28% 单核 CPU；DSH 分别为 23.19% 和 16.77%。第二段确认聊天队列、活动会话和待执行操作均为空。网关和生图 worker 当时基本空闲。NapCat 的监听进程不能代表整个 QQ 多进程资源占用，本报告不把它当作完整协议端测量。

框架优化前 RSS 约 399–437 MiB；15 秒 profile 期间 JS heapUsed 从约 109 MiB 回落到 57 MiB，文件描述符稳定，未观察到持续增长证据。这只能说明短时样本没有证明泄漏，不能排除长时间或特定业务下的泄漏。DSH 有换出页面，采样和重新启动都会影响 RSS；内存变化不能全部归因于代码优化。

## 实际热点与修改

| 位置 | 观察 | 修改与保留语义 |
| --- | --- | --- |
| 入站队列与 SQLite | 每 250ms 扫描、解码保留的空队列；深拷贝在 profile 中约占 13.77% 总采样时间 | 变更令牌跳过空闲扫描，活动队列仍读取并核对期限、就绪和 CAS；跨连接提交、时钟回拨和跟踪容量淘汰使缓存失效；记录保持完整校验与深冻结 |
| DSH 工具通道 | 没有聊天任务时，15 秒内仍发送 79 个 `pollFrameworkTools` 请求 | 空队列最多等待 1 秒，有调用立即唤醒；活跃任务保持短轮询，取消、关停清理等待器，旧插件兼容 |
| 本机鉴权 | 每个 RPC 重读、解析凭据并签名，profile 约占 6.11% 总采样时间 | 每次保留安全路径、权限及文件 revision 校验；文件不变时复用即将到期前可更新的 cookie，并发共享检查，轮换、撤销或时钟回拨时不复用旧凭据 |
| DSH 配置发现 | 反复解析 YAML，发现入口约占 5.67% 总采样时间 | 完整文本键缓存冻结只读值；32 项、8 MiB 源文本、60 秒有效期；编辑 AST 独立，不缓存部署结论 |
| 空任务索引 | 第二轮 profile 发现已为空的 tasks.pending 仍每 250ms 查询 | 只有首分页确认为空且变更令牌未变时跳过，未来任务和遍历尾页继续原有检查 |
| 插件日程 | 每秒重复时区计算，未到期仍写入进度 | 有界纯计算缓存；跨过实际发生点才持久推进，保持 DST、重启、回拨、未知结果不重放；登记即时回收，后台回收每分钟执行 |
| 插件热重载 | 每代源码全部保留，代次上限未约束累计源码字节 | 未变源码共享文本，默认 64 MiB 去重源码预算并保留 64 代上限；旧任务与延迟 import 仍使用原代，预算不是总堆内存上限 |

上述 profile 比例是包含 idle 的总采样时间占比，调用栈的包含时间可能重叠，不能相加作为 CPU 降幅。

## 部署后的对比

首次重启后的样本为框架 7.60%、DSH 1.48%，但当时工具通道尚未被首次聊天启动，不能把这个差异全部归因于优化。为对齐空闲轮询状态，在框架进程内临时运行同版本 `createFrameworkToolPump`，使用实际 DSH 适配器、鉴权与协议端点；观察器不接受任何调用、不登记模型工具、不发送消息，并在每段采样后停止、关闭连接。进程内 Inspector 只用于安装和清理观察器，资源采样仍来自 `/proc`。

| 指标 | 优化前 | 优化后：同一生产轮询代码的只读观察器 |
| --- | --- | --- |
| 框架平均 CPU（单核口径） | 58.28% / 66.94% | 9.49% / 8.21% |
| DSH 平均 CPU（单核口径） | 16.77% / 23.19% | 5.77% / 5.84% |
| 框架 RSS | 399–437 MiB | 214–217 MiB |
| 空工具查询频率 | 79 次 / 15 秒，约 5.27 次/秒 | 38 / 39 次，各 45 秒，约 0.84–0.87 次/秒 |

每段 CPU 样本约 30 秒；新版观察器分两段各完整运行 45 秒，状态维持 running、错误为空、没有执行中的工具。这里确认的是低负载和空轮询成本下降，不是模型响应速度或高并发吞吐量承诺。后台接收真实 QQ 事件、系统分页、JIT 和重启都会造成波动。

第二轮 CPU profile 中，`values.copy` 所在模块的自耗时从约 13.77% 降至约 0.62% 的总采样时间；鉴权和 YAML 不再是前列热点。该 profile 进一步定位到空任务索引的重复 SQL 查询，本轮随后也加入变更令牌优化。

## 复查与验证边界

做了首轮运行采样、实现后的交叉人工审阅，以及部署后的运行采样。交叉审阅发现并修复带 TTL 队列在存储时钟回拨后重新可见的边界，同时为命名空间变更跟踪加入 1024 项容量限制。

完成部署所需的框架、网页、SDK 和 DSH 桥接插件构建。补充回归用例但按项目约定没有运行自动化测试、压力测试或模拟聊天；运行状态与资源采样不能代替全部业务场景验证。部署后确认原生聊天与协议连接恢复、11 个包运行、21 个服务就绪，插件热重载登记无错误；QQ 会话绑定、插件会话绑定与空间日程的前后快照一致，协议端登录保留。

最近活动最多 100 条，事件流、订阅缓冲、入站队列及渲染并发均已有上限，本轮未发现这些结构无限增长。V8/Node 的已编译 ESM 无法按普通对象方式卸载，热重载仍需要代次和源码容量边界。后续应在长时间真实聊天和频繁重载下继续观察，不能以本轮短时下降宣称彻底消除内存泄漏。

原始 profile、进程快照与运行状态保留在本机私有目录；公共报告不包含凭据、真实账号和聊天内容。
