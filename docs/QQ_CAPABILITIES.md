# QQ 协议能力清单

核对日期：2026-10-28。当前运行协议端自报 **NapCat.Onebot 4.18.41**。以下依据本机安装版本的实际 action 注册表、框架适配器及模型工具注册链路整理；接口存在不等于 QQ 服务端一定接受，也不代表已逐项实机执行。

## 当前接入范围

| 类别 | 已内置 | 主要缺项 |
| --- | --- | --- |
| 群内自身资料 | **修改当前群自身名片，本次补齐** | QQ 昵称、头像、签名、在线状态；修改其他成员名片 |
| 消息与互动 | 文字、图片/GIF、语音、文件、QQ 表情、引用、@成员、合并转发、戳一戳、撤回自身消息 | 消息贴表情、资料点赞、已读/输入状态、直接转发原消息、群签到 |
| 收藏表情 | 查询已有收藏、读取、按场景发送 | **新增收藏、删除收藏、修改描述**；QQ“收藏内容”另有独立接口，当前也未接 |
| 会话与资料查询 | 当前群资料、成员、当前会话历史、单条消息、好友/群目录 | 原生工具缺用户资料、分组好友、最近联系人、群荣誉、禁言名单、精华、公告等查询 |
| 好友与入群 | 入站事件接入扩展事件体系 | 同意/拒绝好友与入群请求、可疑申请处理、备注、删除好友 |
| 群管理 | 自身群名片 | 群名/头像、其他成员名片、头衔、禁言、踢人、管理员、退群、公告、精华、群待办及加群规则 |
| 文件 | 当前会话附件读取、发送群/私聊文件 | 群文件列表/文件夹、移动/重命名/删除、在线文件夹、闪传及文件集管理 |
| 空间与相册 | 文字/图片/图文说说发布、删除 | 当前 NapCat 注册表未提供说说读取/点赞/评论；群相册接口存在但框架未接 |
| 语音与识别 | 语音资源读取及发送；图片/GIF/视频抽样走媒体链路 | NapCat 语音转文字、OCR、AI 语音未接入原生工具；音频转写仍需单独服务 |
| 连接与运维 | 登录身份、在线状态、版本核验由宿主使用 | 在线设备、其他诊断、重启/退出/缓存清理不作为默认聊天工具 |

消息段也有独立边界：当前结构化发送支持 text、image、audio、file、face、mention、reply、forward；视频按文件发送不等于原生 video 消息，骰子、猜拳、位置、名片/Ark 等也没有专用结构化出口。不能仅凭 send_group_msg 已接入就认为所有 QQ 消息类型均可发送。

## 能力与权限

- 工具目录描述“能做什么”，宿主负责“谁能在什么范围做”。目录中的主人校验等说明是**当前调用边界**，不把权限写成能力名。
- `qaf_group_card({card})` 允许 AI 在当前群自主调整自己的名片，也可按真实主人要求修改。框架从可信上下文确定群号和自身账号，模型不能传其他成员或其他群；普通成员建议是否采纳属于聊天策略，不伪称宿主能识别模型的“自主意图”。
- 群管理员/群主角色是 QQ 侧限制；框架主人的身份不自动获得 QQ 管理权限。未来群管理工具需要单独设置作用域和敏感操作身份校验。
- 不提供把任意 action 与参数直接交给模型的通用透传口。凭据、原始包、重启和退出等属于底层运维，不因协议有接口就成为日常聊天能力。
- 自身群名片使用标准 OneBot 动作，不依赖 NapCat 私有路径；SnowLuma 切换后沿用同一适配器，以实际返回为准，本次未启动 SnowLuma 做实机验证。其他扩展动作须分别适配，不能宣称两个协议端功能完全等同。

## 建议补齐顺序

1. 日常交互：新增/删除收藏表情、描述维护、消息表情回应、用户资料、自身 QQ 昵称/签名。
2. 管理工具：好友与入群请求、备注、公告、精华、群资料，以及明确授权范围的群成员管理。
3. 文件与相册：群文件浏览管理、群相册、在线文件与闪传；按实际需求独立接入。

本次只新增自身群名片工具，其余缺项均保持清单状态，没有因为列入规划而向模型注册。

## 维护依据

框架事实入口：`src/host/native-chat-runtime.ts`（实际注册）、`src/host/native-conversation-tools.ts`（会话基础工具）、`src/host/native-sticker-tools.ts`、`src/host/native-qzone-tools.ts`、`src/adapters/onebot*.ts`（协议适配）。`onebot-compat.ts` 的兼容代理白名单单列，不能视为原生聊天工具。控制台目录由 `src/host/native-tool-inventory.ts` 投影。

协议侧依据当前安装的 `napcat.mjs` action 注册表及各处理器声明，版本由只读 `get_version_info` 核对。此文为该版本快照；升级协议端或新增框架工具后同步核对，不从 API 名称推断已打通的能力。
