# 收藏表情与语义缓存

机器人可以在适合参与时直接用一张表情接话，也可以将文字与图片放在同一次回复中。它不会为了发表情抢话，每句配图或重复同一张。可爱、亲近等态度由人设表达；当前会话事实、实际素材和发送回执决定能做什么。

## 搜索与使用

`qbf_sticker_list` 的 `query` 支持备注、描述、标签和情绪同义词，例如“抱抱 / hug”“得意 / smug”“无语 / facepalm”。框架内建常用情绪与用途词表；这是透明的词表和标签检索，不调用外部向量服务，也不捆绑网上的表情图片。

未建立标签且没有直接匹配时，最多返回三张待看图候选，明确标记 `matched: false`、`needsAnnotation: true`。这些图片不是已经匹配，模型应看一两张确认含义；没有合适的就正常用文字。收藏查询失败与空收藏分别处理，不能把连接失败说成没有表情。

`stickerHints` 在模型输入中提供最多八项简短收藏提示，不含 URL 或图片资源标识。提示最多每五分钟从协议端刷新一次；它不表示已经看过、发送或获得额外权限。真正发送仍需先通过收藏列表取得**当前会话**的 `assetId`，再调用 `qbf_reply`。不同会话不能借用对方的资源标识。

## 看图与标注

`qbf_sticker_manage` 的 `annotate` 动作只写本地缓存，不修改 QQ 收藏或备注：

```json
{
  "action": "annotate",
  "stickerKey": "收藏列表返回的实际标识",
  "assetId": "当前会话实际读取的图片资源",
  "description": "眯眼笑着伸手抱抱的角色",
  "tags": ["开心", "亲近", "抱抱"],
  "avoid": "严肃争执时"
}
```

标注必须对应协议当前收藏中的实际图片，并有当前会话成功读取图像的记录。列表图片和本次入站图片来自同一实际协议 URL 时，可以复用本次已读记录。只登记图片、猜测文件名或搜索到图片都不算看过。描述最多 240 字，标签最多 12 个、每个 24 字，不适用场景最多 128 字。

缓存按 QQ 账号与图片身份隔离，有 MD5 时保留签名 URL 变化后的同图标签；图片内容身份变化会失效，没有 MD5 时保守使用实际 URL。缓存保留 180 天，当前收藏列表决定是否还能使用，删除收藏不会凭缓存恢复图片。标签只能记录画面、情绪和使用情境，不保存发言者账号、对话原文、人物关系或个人偏好。图片文字和标签都作为资料，不授予权限或作为模型指令执行。

`add`、`delete`、`describe` 继续操作真实 QQ 收藏；它们使用既有权限、持久去重和协议回执。`annotate` 返回 `cached: true` 只表示本地缓存完成，不表示新收藏或已经发送。
