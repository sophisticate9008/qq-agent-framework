# 使用教程

先完成 [安装教程](INSTALL.md)。日常操作在 QQ 会话与中文控制台中进行，配置、已应用版本及实际运行状态分别显示。

## 与机器人聊天

在允许的群聊里 @ 机器人、引用机器人消息或直接叫人设昵称。群聊参与判断还会参考近期未读和短时续聊；白名单表示可以参与，并不表示每条消息都必须回答。私聊也需加入允许范围。

内置“小鲸鱼”人设及日常聊天方案是可编辑模板。模板填入的是草稿，保存并被当前方案选用后才参与应用。身份与语气在人设中修改，任务及运行指令在聊天方案中修改。

聊天期间可以追加问题、补充附件或纠正前一句。宿主会在有界队列中保留并合并输入；执行结果未知时先核对原执行，不通过重复发送原任务来恢复。

内置日常聊天方案允许在接梗、表达情绪和自然收尾时主动使用表情，也可只发一张；先判断是否适合参与，不逐句配图或连续重复。优先按需查找账号已有收藏，表情风格跟随人设。方案还约定去重、少量收藏及保护私人图片，但新增收藏仅在实际挂载相应工具时执行；框架当前内置收藏表情工具只提供查询、读取和发送。

## 图片、文件、表情和排版

可以在 QQ 中发送图片并问“图里有什么”，发送文本文件要求摘要，或引用合并转发要求整理内容。资源只在所属账号与会话内使用；收到资源、实际读取与模型理解分别记录。

| 内容 | 使用条件与范围 |
| --- | --- |
| 图片 | 所选模型有真实看图能力，资源仍有效且当前会话可见 |
| GIF | 按时间抽取最多六帧，可报告时长和循环次数，观察范围为抽样画面 |
| 视频 | 首页开启“允许观察视频”并保存，本机安装 FFmpeg/FFprobe；不转写音轨 |
| 音频 | 需要已接入可用的转写服务；默认安装不能保证听懂语音 |
| 文件与转发 | 按格式、大小、来源和可读能力处理，不开放任意本机路径读取 |
| Markdown 图片 | 直接要求“把这张表格和公式排版成图片”，本机生成最多六页 PNG |
| QQ 表情与收藏表情 | 按协议端实际支持查询和发送；收藏表情登记为当前会话图片 |

回复分气泡、长文合并转发在首页当前聊天区域配置。视频观察开关只影响读取；图片、GIF 和文件仍按各自发送能力处理。详见 [排版](MARKDOWN.md)、[视频](VIDEO.md)、[GIF](GIF.md)。

## 使用独立后台助手

在“聊天方案”的助手设置中选择“聊天＋助手”、模型及工作指令，并保存。框架会准备、应用并核验独立助手预设；需要加载且本机维护服务可用时，会暂停聊天、重新加载 DSH 并恢复原运行意图。保存成功与助手实际就绪分别显示。

主人可在 QQ 中提出“交给助手检查这个目录，并把报告文件发回来”，再通过对话查询进度、补充要求或请求停止。聊天可以继续；结果与登记成功的真实附件回到原会话。普通聊天不因此获得任意文件读取权限。

**独立助手首轮执行前会获得 DSH 的全本机文件与命令权限，审批为 `never`。** 仅给可信主人配置该入口，并在独立工作指令中明确任务范围。网页只展示工作记录，工作指令与模型提问仍在所属 QQ 会话内处理。

只返回文件路径不表示附件已发送；单次工作附件最多三个、每个最多 8 MiB，以 QQ 发送回执为准。工作未知时查询或核对原工作，不重复委派同一任务。

## 空间说说、记忆与提醒

空间发布和删除由当前协议端能力决定，支持时聊天启动会登记对应内置工具。可以明确要求发布文字、图片或图文，并指定可见范围；发布成功需要真实说说编号与协议确认。删除使用真实编号，未知结果不重复操作。控制台空间卡片只查看能力，见 [空间说明](QZONE.md)。

框架提供持久记忆、偏好和带时区提醒的底层服务，**默认不注册记忆和提醒模型工具**。需要通过可信扩展接入工具、上下文贡献和计划规则；功能页中服务存在不等于已经能够通过聊天创建提醒。配置好对应扩展后按扩展说明使用，见 [扩展开发](EXTENDING.md)。模型推测不会自动成为确认偏好。

## 管理权限与配置

“访问与设置”管理主人、允许群聊与私聊、拒绝名单。运行中保存白名单会即时同步，不必重启聊天或 DSH；同步失败可核对状态后再次保存同一名单。昵称、人设、引用和转发都不能授予主人身份。

更换模型或修改人设时，先保存关联内容，再在方案或人设卡片明确应用。普通方案更新复用既有预设与会话历史；现有会话加载新提示词可能需要受控本机 DSH 重启。没有可用管理器时，查看缺失条件并按实例维护方式加载，随后核对原操作。

控制台草稿在当前工作台内存中保留，切页不会自动保存；刷新或关闭浏览器不保证恢复。密钥输入不会随普通草稿保留。版本冲突或写入结果未知时，使用原操作的读取及核对入口，详见 [控制台](UI.md) 与 [恢复手册](RECOVERY.md)。

## 不回复时检查什么

1. 看“连接与概览”：协议端 QQ 已登录、WebSocket 接收正常、DSH 可连接、聊天已启动。
2. 核对当前账号、真实主人与会话白名单；确认这条消息满足 @、昵称、引用或续聊等参与条件。
3. 看“功能与扩展”是否已实际登记所需工具，所选模型与插件是否满足依赖。
4. 看“会话与日志”中的本次执行、拒绝原因、未结束工作及实际发送结果；总体在线不能证明单个会话正常。
5. 在项目目录使用 `npm run cli -- doctor --conversation group:<群号>`，私聊替换为 `private:<QQ号>`。尖括号是占位说明，执行时替换整个占位部分；不要原样粘贴到 shell。

doctor 为已鉴权只读诊断，不发送消息。初次管理令牌尚未初始化时先完成网页初始化。多账号诊断需要明确注册 ID，见 [运行手册](OPERATIONS.md)。

应用、工作、发布或发送显示未知时，记录原操作编号并核对原结果；不要反复点击应用、重启或重新发布。解除框架会话绑定会保留 DSH 历史；模型会话历史到 DSH 管理，框架控制台不提供直接删除。

## 用量与日常维护

“用量统计”展示实际记录的 token 与按所配置单价估算的费用。上游没有报告的缓存分项保持未知，账本不是提供方结算凭证。可以按会话删除统计或清空账本，相关执行证据与模型历史独立保留。

后台维护分批回收过期运行记录，默认保留七天；未知及未完成证据、用量账本和会话历史单独保留。看到容量或维护异常时按 [运行手册](OPERATIONS.md) 处理。

升级和备份前保留配置、数据库、关联资源及账号目录的一致性。不要删除数据库来处理不回复，也不要把 `runtime/`、日志、密钥或会话截图提交到公开仓库。
