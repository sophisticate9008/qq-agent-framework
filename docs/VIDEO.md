# 内置视频观察

在首页“连接与概览”的当前聊天区域开启 **允许观察视频**，保存后立即生效。默认关闭。开关只控制视频内容读取，不改变聊天白名单、主人身份或发送权限。

开启后，模型可以按对话需要读取本会话已登记的视频。框架下载协议端提供的实际视频字节，使用本机 FFprobe 检查视频流，再通过 FFmpeg 在前、中、后等时间位置抽取画面，将真实图片及时间点交给模型。收到视频不等于立即下载或分析。

关闭时仍可显示视频已收到，但读取请求会返回关闭状态，不下载、不抽帧。关闭后的新请求不能复用读取入口绕过开关；已经进入模型上下文的历史画面不会因此自动删除。

## 当前范围

- 支持 MP4/MOV 与 Matroska/WebM 容器，以实际解码结果为准。
- 每段视频最多 64 MiB、10 分钟，最多返回六张不同时间点的画面。
- 时间点使用解码后的真实画面时间，不把期望抽样时刻伪装成实际时间。
- 抽样图片最长边不超过 960 像素，总图片字节不超过 360 KiB，避免持续挤占上下文。
- 本轮只观察抽样画面；快速动作或两个抽样时间点之间的变化可能未被看到。结果会注明抽样范围。
- 可检测是否含音轨，但当前不转写视频声音。画面中的文字、模型推测和实际听到的声音不能混淆。

视频作为普通文件上传时，常见视频后缀也会进入同一观察入口，最终仍需验证实际容器。伪造后缀不能跳过解码和容量检查。

## 运行依赖与清理

观察服务属于框架内置能力，自动查找稳定安装路径中的 `ffmpeg` 和 `ffprobe`。本机已有这两个程序时直接使用；缺失时返回明确的依赖不可用状态，不把视频已登记说成已经看过。新部署需通过系统包管理器安装 FFmpeg；运行代码不依赖 `/tmp` 中的程序，也不会在聊天请求期间下载执行文件。

FFmpeg 只处理框架受管目录中的已下载字节，不接收模型指定的 URL、路径、shell 或任意参数。读取器沿用协议资源的来源校验；解码器限制容器、分辨率、并发、帧数和总时限，禁用网络与外部引用。单次观察结束、取消或失败后删除临时视频，异常退出残留在后续观察时有界清理。

该能力使用普通 OneBot 视频入站资源，与协议端的消息发送能力独立。某个协议端未提供可下载的地址或有效文件查询结果时，会如实报告资源不可读，不猜测路径或向其他会话查找视频。
