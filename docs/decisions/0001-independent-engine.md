# ADR 0001：独立 TypeScript 桥接引擎

日期：2026-10-24。状态：接受；第一轮只做离线内核与演示。

## 背景

用户要求工程上的自我迭代能力：工作 agent 能扩展桥接能力，而不是把需求误判成某次会话的偏好。
旧桥接已改动较多；用户明确选择参考它，自建独立框架和 UI，并授权单独公开建库。
DSH 作为成熟的模型/工具执行底座，只通过适配器接入，不在本项目重建。

## 决策

- 独立仓库、原创建模与实现，不搬运旧源码、配置、人格或素材。
- 手写程序统一 TypeScript，strict 检查覆盖内核、前端、脚本与测试；生成 JS 只在 dist。
- 第一轮仅内存实现和无网络演示，证明功能装配、权限边界与数据分类。
- 使用版本化功能 manifest、通用宿主事件/能力挂载点及统一副作用检查。
- 原项目和已成功成果保持原状；保留转向前的局部原型，不擅自部署或清理。
- 并行分成数据服务、管理 UI、适配器/示例三组；主线程负责内核、整合、证据与发布。

最初请求的 gpt-6.1-sol 在本工具中不可用，未暗中替换；用户明确改用后，三个子代理统一
使用 gpt-5.6-sol high。此项是本轮开发记录，不是框架运行时的模型配置。

## 代价与拒绝项

首轮不覆盖任务恢复、真实 QQ/DSH 会话、图像生成、调度或动态代码部署。
同步安装与清理降低复杂性，但不能执行异步 setup 或强制终止不合作代码。
框架尚无成熟依赖图/schema 发布/迁移系统；不把最小引擎冠以生产成熟度。

后续每个基础能力通过独立契约和证据升级，不以“功能 active”代替全链路可用。
