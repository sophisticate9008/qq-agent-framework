# ADR 0001：独立桥接引擎与适配器边界

日期：2026-10-24
状态：接受

## 背景

QQ 协议接入、外部 agent 会话、功能行为、权限和运维具有不同生命周期。把这些职责集中在单一桥接入口中，会使功能迭代依赖协议细节，并扩大故障与授权影响范围。

## 决策

- 使用独立 TypeScript strict 项目维护框架契约和实现。
- 核心引擎只负责功能生命周期、事件调度、上下文、权限和受控副作用。
- QQ 协议、外部 agent、存储和资源访问通过显式适配器或宿主服务接入。
- 功能以版本化 manifest 声明事件与 capability，不直接取得网关、凭据或完整宿主对象。
- 人设、配置、偏好、状态、资源和权限分别建模。
- 跨重启语义由持久会话、任务和出站记录提供，不把内存去重描述为可靠交付。
- 外部系统已成熟的能力通过适配器复用，不在框架内重复实现。

## 结果

功能可以独立开发和测试，协议与 agent 实现可以替换，权限检查集中在稳定边界。代价是宿主需要明确装配更多组件，并为适配器、恢复和数据迁移编写集成测试。

该决策不提供不可信代码沙箱、exactly-once 交付或外部动作回滚。任何生产可用结论仍取决于具体适配器和部署验收。
