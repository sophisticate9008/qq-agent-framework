## 发现、修正与保留的失败

- 集成发现 UI 默认会话与宿主演示范围不一致，改为 demo:room，并补静态断言；不能只信各自模块单测。
- 补充观察者与实际动作的授权边界测试，避免在最终授权和适配器调用之间调用可重入 observer。
- 增加未完成事件/副作用数量限制，避免内存历史上限被误认为排队上限。
- 明确传输拒绝与未知结果，两个示例均只在 confirmed 时增加送达计数。
- 补齐通用事件和能力挂载点，原有两个内置路径不能被扩展同名替换。
- TS 迁移时修复真实的边界类型、DOM 类型和测试 deferred/回执类型，没有用 any 或禁用检查掩盖诊断。
- 第一次编译产物测试57通过、1失败：测试仍读取 dist/web/app.ts。改成按当前执行形式检查源TS或编译JS，
  保留初次失败日志，随后整组重跑。浏览器路径始终为 /app.js，不把 TS 作为脚本直接发给浏览器。
- 源语法检查发现前端缺少显式模块标记，Node 的 check 路径按普通脚本解析类型声明。
  加入空模块导出，与页面已有 type=module 一致；保留 check-first-run.log 后重跑检查和页面验收。
