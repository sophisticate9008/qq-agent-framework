# 空间生活日记示例插件

这是可选业务示例，使用框架的持久会话、定时任务、能力目录与生图服务，不属于框架默认启用功能。需要安装者另外提供生图服务、角色素材、写作与视觉模型及协议连接；接口可接入不同生图实现。业务源码不包含账号、角色素材、供应商凭据或运行数据，也不打入 SDK 或 DSH 桥接插件安装包。示例入口和依赖清单见 [组合服务示例](../../examples/qzone-diary/README.md)。

## 日常流程

1. 每天在配置的本地时间窗口中选取 1–3 个时间点，并由独立持久会话安排符合这些时刻的生活片段。计划先持久保存；重启沿用当天安排。
2. 到点后在同一写作会话中生成第一人称短文案和画面要求。生图服务在内部加入自己的形象参考，画风、场景、服装与动作可以变化。
3. 将实际生成图片作为原生图像附件送给配置的视觉模型，检查肢体、手指、面部、物体关系、文案匹配和明显水印等问题。模型检查可能漏判，不是图像质量的绝对保证。
4. 不通过时按检查意见重新生成，最多两次，即总共三版；第三版仍不通过则跳过这一条。生成失败、检查不明确或执行未知都不会冒充通过。
5. `publish: false` 停在审查通过的预览；`publish: true` 使用宿主协议能力发布图文，只有明确回执才标记发布成功。预览可通过 `publishApproved` 执行同一个最终发布步骤，无需再生成。

写作会话固定绑定实际 DSH 会话，可在会话管理中查询或换绑。首次进入新的写作会话注入插件角色说明和最多五条已发布摘要，后续使用会话自身历史；不装配 QQ 聊天方案和工具。视觉审查使用独立单次会话，避免图片不断累积进写作上下文。

## 接入

可信 bootstrap 调用 `createQzoneDiaryPackage`，传入私有存储、配置读取函数、图片产物存储及提供生图服务的包标识。安装方同时提供框架的 `plugin-runtime` 包。日记包通过共享契约声明并取得 `image-generation`、`plugin-models`、`plugin-protocol`、`plugin-scheduler`、`plugin-tools` 和 `plugin-extensions` v1 服务；依赖缺失或版本不匹配时在启动前拒绝。

生图包声明并发布 `IMAGE_GENERATION_SERVICE_CONTRACT`，接口为 SDK 的 `ImageGenerationService`。服务返回实际图片字节，不自动向 QQ 发送；协议发布复用绑定插件身份的协议服务与幂等回执。

配置包括 `enabled`、`publish`、`timeZone`、`persona`、写作 `model`、`visionModel` 和 `windows`。模型选择沿用已配置供应商标识；视觉模型必须声明图像输入能力。

`windows` 用本地日内分钟表示。例如 `[{start:600,end:750},{start:900,end:1050},{start:1170,end:1350}]` 对应 10:00–12:30、15:00–17:30、19:30–22:30。每个窗口至少一小时，互不重叠。实际发布时刻在其中随机选择，预留至少三十分钟处理时间；计划生成变慢时仍可在原窗口内顺延，窗口已结束则跳过。默认每日 08:30 检查计划；首次启动会检查当天是否已有计划。

`createLocalDiaryMedia` 适用于框架和协议端共享本机目录的部署，使用私有目录、实际字节哈希及发布前核对。远程协议端应提供独立 `DiaryMedia` 适配器，将已审查产物转换为协议端可读取的资源。

## 管理与恢复

- 控制台“任务与日程”统一展示插件登记的规划、发布任务和调度历史。详情显示关联写作会话、文案、图片缩略图及生成、检查、发布阶段；“调度完成”与“已发布到空间”分别呈现，只有协议确认后才显示已发布。详情读取不会生成内容或发布消息。
- 页面暂停任务会保存宿主调度覆盖，重启或插件再次登记不会清除。暂停影响后续触发，已开始的工作继续按原流程结算；恢复不补跑已经过期的时间段。
- 尚未开始的发布安排可“跳过本次”：先把插件的这条日程记为已跳过，再由宿主取消对应触发器；不删除业务历史，也不会在插件恢复安排时重新登记该条。正在执行或结果未确认的条目不提供跳过操作。
- 本机媒体适配器为详情提供受限的 WebP 缩略图，只从已登记的图片产物读取，浏览器不接收本机路径。图片不可用时仍可查看文案与业务状态。其他部署可实现可选的 `DiaryMedia.preview`；未实现时保留文字详情。
- 模型通过能力目录找到 `extension.qzone-diary.status`、`plan`、`set-enabled`。它们分别查询今日状态、检查计划和启停插件，QQ 调用要求实际主人；自主调度使用宿主插件身份。主人在 QQ 说“恢复今天的空间日记规划”时，使用 `plan` 的 `{ "recover": true }` 登记恢复检查。返回“已登记”表示任务已入队，最终结果通过 `status` 或“任务与日程”核对。
- 开关在生成和发布前重新读取。禁用后不再开始后续生成或发布；已经送往外部的请求不能靠改开关撤回。
- 规划失败保留原日期、尝试次数及最近十六次失败记录。当天没有任何日记或发布规则，且原模型会话已就绪时，间隔至少五分钟自动恢复规划，当天累计三次尝试后停止自动恢复。重启保留次数与原重试任务；过期窗口与跨日恢复任务不补跑。已保存的完整计划只恢复缺失日程，不重新生成。
- 手动恢复允许在修复原因后继续尝试，至少间隔一分钟；仍核对会话状态、已有日记及发布规则，保留原会话和历史。没有绑定、会话忙或模型执行结果未知时，恢复会明确受阻；在“插件模型会话”使用已有核对入口确认原执行后，再从 QQ 请求恢复。不通过新建会话、删除当天记录或修改未知回执绕过核验。
- 正在生成、检查或发布时发生进程中断，记录转为 unknown，保留证据且不自动续发。规划恢复不处理这些发布步骤；已有部分日记需要先核对原记录。当前实现没有自动核对已发布说说的通道，需按协议实际回执和空间页面检查。
- 已结束的日程及无引用图片保留七天。未知记录和仍被引用的图片保留；日程最多 366 条，达到容量上限停止新增，避免无限增长。通用调度另有规则与历史容量限制。
- 配置读取和 `setEnabled` 写入由安装方提供。底层生图扩展继续使用自己的热重载机制。

## 工作流热重载

包启动后登记 `qzone-diary` 热重载项。更新工作流实现后先执行 `qqbridge-framework extensions` 查看当前登记，再执行 `qqbridge-framework extensions reload qzone-diary`。候选模块按源码指纹加载，固定 v1 行为契约不兼容或加载失败时保留旧代；同一源码版本不切换。固定入口 `index.ts`、行为契约 `workflow-contract.ts`、输入类型 `types.ts`、管理贡献 `management.ts`、恢复核验 `planning.ts`、媒体适配器 `media-store.ts` 和时间换算 `time.ts` 的指纹在加载前后核对，修改这些文件会拒绝热重载，要求完整重新应用装配。工作流和其本地依赖采用有界 ESM 代际缓存，最多 64 个源码版本，达到上限后需重新应用宿主版本。

工具和定时任务 handler 只在包首次启动时注册，各次完整执行持有对应工作流代的租约。新调用使用新代，已开始的规划、生成、检查或发布沿原代排空；旧代排空前不接受下一次重载。候选构造不调用 `start()`，不会重复登记 handler、更新每日规则、执行中断恢复或将仍在运行的日程改成 unknown。所有代继续使用同一持久日程和模型绑定，不因重载重排当天计划或重放发布。

包停止时先撤销固定工具、handler 和热重载登记，再关闭管理器并等待各代排空。进程退出仍遵守上述未知记录恢复语义。工具 schema、handler 输入、行为契约版本、依赖声明、包入口和媒体存储适配器变化需要完整重新应用装配；热重载只替换工作流行为及它实际导入的本地实现。

## 验证

`test/qzone-diary.test.ts` 使用真实 SQLite、框架会话服务、调度服务和能力服务，模型及协议端用确定结果替身验证控制流程。真实模型、真实生图及协议发布验证另行留在本机私有目录，不把替身测试当作真实送达证明。

规划失败详情会区分模型会话恢复、模型配置、会话忙碌和上下文准备失败。后续恢复成功后，任务详情显示当前已安排条数；原失败或中断的执行历史保留，并注明后续规划已成功，避免把旧执行结果误认为今天仍没有计划。
