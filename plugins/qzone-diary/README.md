# 空间生活日记插件

这是可选扩展，使用框架的持久会话、定时任务、能力目录与生图服务。业务源码不包含账号、角色素材、供应商凭据或运行数据。

## 日常流程

1. 每天在配置的本地时间窗口中选取 1–3 个时间点，并由独立持久会话安排符合这些时刻的生活片段。计划先持久保存；重启沿用当天安排。
2. 到点后在同一写作会话中生成第一人称短文案和画面要求。生图服务在内部加入自己的形象参考，画风、场景、服装与动作可以变化。
3. 将实际生成图片作为原生图像附件送给配置的视觉模型，检查肢体、手指、面部、物体关系、文案匹配和明显水印等问题。模型检查可能漏判，不是图像质量的绝对保证。
4. 不通过时按检查意见重新生成，最多两次，即总共三版；第三版仍不通过则跳过这一条。生成失败、检查不明确或执行未知都不会冒充通过。
5. `publish: false` 停在审查通过的预览；`publish: true` 使用宿主协议能力发布图文，只有明确回执才标记发布成功。预览可通过 `publishApproved` 执行同一个最终发布步骤，无需再生成。

写作会话固定绑定实际 DSH 会话，可在会话管理中查询或换绑。首次进入新的写作会话注入插件角色说明和最多五条已发布摘要，后续使用会话自身历史；不装配 QQ 聊天方案和工具。视觉审查使用独立单次会话，避免图片不断累积进写作上下文。

## 接入

可信 bootstrap 调用 `createQzoneDiaryPackage`，传入私有存储、配置读取函数、图片产物存储及提供生图服务的包标识。该包声明并发布 `image-generation` v1 服务，其接口为 SDK 的 `ImageGenerationService`。注册的生图服务返回字节，不自动向 QQ 发送；协议发布复用 `runtime.capabilities` 的幂等调用。

配置包括 `enabled`、`publish`、`timeZone`、`persona`、写作 `model`、`visionModel` 和 `windows`。模型选择沿用已配置供应商标识；视觉模型必须声明图像输入能力。

`windows` 用本地日内分钟表示。例如 `[{start:600,end:750},{start:900,end:1050},{start:1170,end:1350}]` 对应 10:00–12:30、15:00–17:30、19:30–22:30。每个窗口至少一小时，互不重叠。实际发布时刻在其中随机选择，预留至少三十分钟处理时间；计划生成变慢时仍可在原窗口内顺延，窗口已结束则跳过。默认每日 08:30 检查计划；首次启动会检查当天是否已有计划。

`createLocalDiaryMedia` 适用于框架和协议端共享本机目录的部署，使用私有目录、实际字节哈希及发布前核对。远程协议端应提供独立 `DiaryMedia` 适配器，将已审查产物转换为协议端可读取的资源。

## 管理与恢复

- 模型通过能力目录找到 `extension.qzone-diary.status`、`plan`、`set-enabled`。它们分别查询今日状态、检查计划和启停插件，QQ 调用要求实际主人；自主调度使用宿主插件身份。
- 开关在生成和发布前重新读取。禁用后不再开始后续生成或发布；已经送往外部的请求不能靠改开关撤回。
- 正在规划、生成、检查或发布时发生进程中断，记录转为 unknown，保留证据且不自动续发。当前实现没有自动核对已发布说说的通道，需按协议实际回执和空间页面检查。
- 已结束的日程及无引用图片保留七天。未知记录和仍被引用的图片保留；日程最多 366 条，达到容量上限停止新增，避免无限增长。通用调度另有规则与历史容量限制。
- 配置读取和 `setEnabled` 写入由安装方提供；业务代码或注册结构变化需要重新应用装配。底层生图扩展继续使用自己的热重载机制。

## 验证

`test/qzone-diary.test.ts` 使用真实 SQLite、框架会话服务、调度服务和能力服务，模型及协议端用确定结果替身验证控制流程。真实模型、真实生图及协议发布验证另行留在本机私有目录，不把替身测试当作真实送达证明。
